# LT100 交互应用与共用底座

- 状态：**v0.2 草案（2026-11-21 教学优先修订）**
- 定位：把“网页孪生、示教回放、光绘、物理仪表盘”等应用收敛到一套**教学优先**的共用底座；不是产品功能清单
- 不在本文：具体 UI 视觉、最终固件实现、采购与结构加工
- 相关：[design.md](design.md)（产品设计）、[common-platform.md](common-platform.md)（公版底座）、[course-4h.md](../teach/course-4h.md)（4h 课）、[kinematics-and-force.md](../teach/kinematics-and-force.md)（运动学）

---

## 1. 结论

0. **教学不是工程的简化版。** 底座优先保证可观察、可复现、可分解、可安全失败、可延伸；工程化细节服从这些目标，而不是反过来。
1. **应用值得做，但先做底座。** 底座不是“一个固件”，而是机械、电气、固件、主机/Web、测试五层；应用只调用统一接口，不直接碰舵机。
2. **A1 的 3D 模型就是操作手柄。** 3D 直接操作负责交互、空间感和光锥；精确性靠数字 q/误差读数和侧视相机预设，不再另做一个可拖的 2D 小窗。
3. **浏览器做规划，固件做安全。** 网页可以 IK、插值、录制；限位、速度/加速度、失联、力矩/温度保护必须在固件，不能被网页绕过。
4. **微雪出厂固件只做舵机调试/恢复，不作为产品底座。** 它是一套单舵机 Web 调试器 + ESP-NOW 演示，不是灯的应用固件；我们自研应用/安全层，底层继续用 `SCServo` 库。
5. **先做“能被验证”的应用：** 3D 直接操作孪生 + IK/ghost 误差；再做示教、覆盖、光绘和演出。

## 2. 产品约束

- **3R 平面臂**：肩、肘、腕三轴平行，只在同一竖直平面内运动；没有偏航/滚转。
- 肩 + 肘负责把灯头送到平面内的位置；腕负责灯头俯仰，决定光束指向、光斑位置和入射角。
- 桌面光斑中心大致由灯头位置和俯仰角决定；**底座 yaw 只能手动转（已确认）**，没有电机/编码器。没有转底座时，光斑中心只沿桌面一条线移动；人转底座才把这条线扫到另一处。扩散片只给这条线增加宽度。
- 没有夹爪、没有视觉、没有力传感器；`load` 不是校准过的力矩/电流传感器。
- 当前没有弹簧/配重、没有机械硬限位；重力由舵机保持，软件标定/限位是唯一保护。弹簧、配重、硬限位都列为改进项目，不当作现状。
- 灯环是状态/氛围光，不是阅读灯；亮度硬上限 40%。

> 这条约束不是“简化版 6 轴”，而是产品本身。应用和课程都应该围绕“平面灯能照到哪、怎么照、为什么站得住”展开。

## 4. 共用底座

### 4.1 机械与电气

底座要“稳定可靠”，先解决物理层；**按现状写，不把改进项当既有能力**：

- **机械硬限位**：当前没有；软件标定/限位是唯一保护。加硬限位是学生改进项目，不是现状。
- **肩部重力**：当前没有弹簧/配重，重力由舵机硬顶；限制水平停留、监控电流/温度；弹簧/配重是改进项目。
- **yaw**：底座只能手动转，三舵机共面只做 pitch；网页只能提示/记录，不能把 yaw 当电机轴。
- **走线与服务环**：灯环线、舵机线分开走；关节处留 2–3cm；硅胶线，避免反复弯折断线。
- **底座稳定**：灯头伸到最远时不翻；底部硅胶脚垫；底座配重。
- **电源**：12V 5A；入口保险丝；灯环 5V 从板载 5V 取，40% 硬上限；连接器/线径按 3A 级留余量。
- **急停/断电**：至少一个可触及的电源开关；调试时手扶手臂。

### 4.2 固件接口

固件是“安全控制器”，不是“网页的遥控器”。具体协议以 [common-platform.md](common-platform.md) 的 `LT100P/1` 为准；下面只是课程级摘要：

```text
POSE <q1> <q2> <q3> [speed] [acc]   三关节目标，度；固件转 raw 并检查限位
STATE                              返回 deg/raw/load/volt/temp/err，10–20 Hz
CAL ...                            零位、方向、每关节 raw 限位；写 NVS
LIMITS                            查询/设置限位
TORQUE <id> ON|OFF                 卸力/上力；示教用
TEACH START|STOP                   记录关节轨迹
PLAY <n>                           回放
PRESET SAVE|GO <n>                 姿态预设
LED ...                            灯环颜色/亮度/状态
STOP                               立即停止并保持
```

约束：

- **单位**：应用层用“度”；固件保存 raw 零位/方向/限位，并负责 `deg ↔ raw`。这样网页/课程不用直接算 4096 刻度。
- **同步写**：三关节用 `SyncWritePosEx`，不要连续发三条独立位置命令；目标是 20–50 Hz 的 `POSE`。
- **状态回读**：`STATE` 至少 10 Hz；网页用它做 ghost/误差/仪表盘。
- **安全**：固件拒绝越界；速度/加速度上限；300ms 无新 `POSE` 自动保持/停止；舵机离线、过温、堵转降级；错误码可读。
- **无硬限位**：标定 + 低速端点验证 + 未标定禁动；标定是安全主线，不是配置项。
- **无弹簧**：监控 `load`/温度；肩部水平停留要限制；弹簧/配重是改进项目。
- **NVS**：零位、限位、预设、灯色；掉电不丢；恢复默认要有命令。
- **非阻塞**：不用长 `delay()`；串口、总线、OLED、LED 状态机化。

### 4.3 主机/Web

- **传输**：优先现有本机 WebSocket 串口桥（`ws://127.0.0.1:8771/serial`），Web Serial 只做回退；桥是单客户端，标定台/孪生页不要同时开。
- **共享模型**：一份关节/连杆/灯头状态、一套 IK；3D 是主视图，2D 只作为侧视相机预设/数字读数，不另写一套。
- **精确读数**：数字 q、目标/实际误差、safe 条；需要“正对平面”时用侧视相机预设，不做可拖的 2D 目标。
- **3D 直接操作视图**：Three.js 本地化；按 `l1/l2/l3` 程序化搭几何体，不导入 STEP；拖灯头/关节，加桌面、灯头、光锥、轨道相机。
- **录制/回放**：JSON 关节轨迹 + 时间戳；支持示教、光绘、演出。
- **Mock 模式**：不接硬件也能演示 UI/IK；硬件验收另算。
- **模型 vs 实测**：覆盖图、光斑、电流条要标明是模型预测还是实测；不要把预测当传感器。

### 4.4 测试与验收

底座没有测试就不算底座：

- Host 测试：IK/FK 往返、限位、角度换算、轨迹插值、协议解析。
- Mock 测试：无硬件跑完整 UI 流程。
- 硬件验收：20 Hz `POSE` 连续 30 分钟不掉线/不复位；`STATE` 10 Hz；越界拒绝；300ms 失联保持；拔舵机降级；NVS 掉电保存。
- 故障注入：舵机离线、灯环断数据、12V 掉压、超温、限位触发。
- 证据：串口日志、状态 CSV、测试脚本 PASS/FAIL，放 `.local/` 或 `docs/validation/`。

## 5. 微雪出厂固件：能复用什么

### 5.1 它是什么

根据本地用户手册（`docs/reference/board/servo-driver-esp32-user-manual-cn.pdf`，§2–§4）：

- 开机建 WiFi 热点（默认 `ESP32_DEV` / `12345678`），手机浏览器打开 `192.168.4.1`；
- 扫描总线、选择一个 Active Servo；显示 ID、位置、电压、MAC、角色；
- 按键：Middle、Stop、Release（卸力）、Torque、Position+/−、Speed+/−；
- 改 ID、设中位、舵机/电机模式、串口转发；
- ESP-NOW Leader/Follower；板载 RGB 彩虹；
- 串口转发时 PC 可以用 Python 直接控制舵机。

它是一套**单舵机 Web 调试器 + 演示固件**，不是多关节灯的应用固件。

### 5.2 复用判断

| 层 | 能否复用 | 说明 |
|---|---|---|
| `SCServo` 库 | **可以** | 官方底层库；`SyncWritePosEx`、`FeedBack`、`WritePosEx` 继续用 |
| 板载引脚/OLED/RGB 初始化 | **参考** | GPIO18/19、OLED 21/22、RGB 23；抽成自己的 HAL |
| 出厂固件的舵机调试 | **可以** | 设 ID、方向、中位、逐个测试；刷我们的固件前先用它验收硬件 |
| 出厂固件的 Web UI | **不建议** | 单舵机手动调试；没有应用协议/限位/预设/轨迹；不能当产品 UI |
| 出厂固件的架构 | **不建议** | WiFi+WebServer+演示逻辑耦合；没有测试/版本/安全边界；默认 AP 密码不适合产品 |
| 出厂镜像 | **保留** | 恢复出厂/排障；本地已有 `factory-firmware-st.rar` |

**结论：出厂固件当“舵机调试/恢复工具”用，产品底座自研。**

自研的范围不是重写舵机驱动，而是写**应用层 + 安全层 + 协议 + 状态机**：

- 用 `SCServo` 做总线读写；
- 自己实现 `POSE/STATE/CAL/LIMITS/TEACH/PLAY/PRESET`；
- 自己做限位、速度/加速度、失联、过温、离线降级；
- 自己做可测试的文本协议和 NVS；
- 网页/3D/课程都建在这层上。

> 本地 `reference/README.md` 记录出厂包是“烧录工具和镜像，不是源码”；用户手册提到 `ServoDriver.ino` 可下载，但本地没有源码快照。即使拿到源码，它仍是演示固件，不建议把产品建在它上面。

## 6. 开发顺序

### Phase 0：底座冻结

- 定 `deg ↔ raw`、零位/方向/限位契约；
- 固件 `POSE/STATE` + `SyncWritePosEx` + 失联保护；
- 机械硬限位、电源保险丝、走线服务环；
- Host 测试 + mock 传输；
- 验收：不接网页，用脚本能连续 30 分钟发 `POSE`、读 `STATE`。

### Phase 1：3D 直接操作与教学核心

- 3D 孪生：拖灯头/关节、IK、目标/实际 ghost、safe 边界；
- Ghost 误差、背隙/重复精度记录；
- 验收：网页拖 3D 模型，实物跟随；越界拒绝；模型与实测误差可量化。

### Phase 2：物理交互与产品叙事

- 手把手示教/回放；
- 阅读/写作/收纳预设 + 灯色 + OLED；
- 3D 舞台/光锥（A1 场景的光效与演出层）；
- 验收：一键预设、示教回放、3D 与实物同步。

### Phase 3：展示与课程扩展

- 光绘、影子剧场、目标游戏、音乐/节奏；
- 物理仪表盘/弹簧对比；
- 语音/手势/手机（可选，最后做）；
- 验收：每个效果可重复演示，有脚本/录像/日志。

## 7. 风险与待确认

| 项 | 影响 | 待确认 |
|---|---|---|
| 底座 yaw/旋钮 | 覆盖是一条线还是一条带 | 旋钮是否可转、是否可加电机 |
| 弹簧/配重 | 保持电流、热、平衡课 | 现结构是否已装；挂点/空间 |
| 机械硬限位 | 软件失效时的安全 | 结构上是否已有限位块 |
| `load` 单位 | 能否做力矩/电流实验 | `ReadLoad` 到底是什么，是否校准 |
| 12V/5V 预算 | 三舵机 + 灯环 + OLED 掉压 | 实测峰值/线径/保险丝 |
| 桥单客户端 | 标定台/孪生页冲突 | 是否扩多客户端或单页整合 |
| WiFi/Web UI | 独立灯 vs PC 宿主 | 先 USB/本机桥，WiFi 后置 |
| 3D 依赖 | 离线/性能 | Three.js 本地化；精确性靠数字读数/侧视相机，不靠 2D 拖拽 |

**不做**：6 轴/视觉/抓取/SLAM/COB 高显色/WiFi 当核心。当前板子没有外部 GPIO，也不适合这些扩展。
