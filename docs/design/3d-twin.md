# LT100 A1 · 3D 直接操作数字孪生

- 状态：**v0.1 方案（2026-11-22）**，待确认后进入实现计划；本文不是已实现功能
- 适用：`09_servo_basic` 固件 + 本机串口桥（`ws://127.0.0.1:8771/serial`）
- 关系：重新定义 [interactive-applications.md](interactive-applications.md) 的 A1。
  A1 不再以“2D 侧视 + 拖目标点”为前置；2D 精确视图如以后仍需要，只作为相机预设/数字读数，
  不另做一个可拖的 2D 小窗。A2/A3/A4 复用本文的运动学、场景和 ghost。

---

## 1. 一句话

浏览器里有一个和实物同尺寸的 3D 台灯。**直接拖灯头或关节**，模型弯下去，
真机按 20 Hz 接收目标并跟随；松手立即 `STOP`；实机位置用半透明/线框 ghost 同时显示。
不是“在 2D 小窗里拖一个目标点”。

## 2. 目标与非目标

### 2.1 目标

1. 3D 模型是**操作手柄**，不是只能看的展示品：拖灯头改位置，抓关节环改单个关节。
2. 真机跟随：拖动期间网页以 20 Hz 发 `POSE`；模型目标 60 fps，实机状态 10 Hz。
3. 目标 vs 实际可分辨：实体模型 = 目标；ghost = `STATE.q` 的实测姿态；显示毫米误差。
4. 一眼看懂安全边界：每个关节的 safe 区间、当前 q、不可达/腕限位都有明确反馈。
5. 不新增固件命令：只用现有 `HELLO / STREAM / STATE / CAL STATUS / LIMITS / POSE / STOP / TORQUE`。
6. 断网、关标签、松手、报错都能停；网页永远不能绕过固件限位。

### 2.2 非目标

- 不做 CAD 导入、不做 2D 可拖目标、不做 6 轴空间臂、不做视觉/相机标定。
- 不做示教录制/回放（A5）、覆盖图（A3）、双解切换（A2）、灯光编排（A7）。
- 不控制底座 yaw：底座是手摇的，没有电机/编码器；模型只允许手动输入一个“底座朝向”做显示。
- 不在孪生页改标定、改 ID、发 `RAW`；这些仍归 09 标定台。
- 不做多客户端：串口桥同一时间只服务一个页面，孪生页和标定台不能同时开。

## 3. 为什么是这套

| 选择 | 采用 | 放弃的 | 理由 |
|---|---|---|---|
| 3D 技术 | **Three.js + 原生 ES module** | React Three Fiber、Babylon.js | 不引入构建链/npm 运行时；离线课堂只需静态文件；场景规模小，直接控制渲染循环更简单 |
| 模型 | **参数化几何** | 导入 STEP/3MF、照片贴图 | `hardware/prints/*.3mf` 是切片 G-code，不含装配网格；`hardware/cad/` 只有控制板 STEP；没有整臂 CAD |
| 交互 | **拖 3D 模型本体** | 2D 侧视拖目标 | 用户明确要“身临其境”；拖模型更直观，且能直接看到关节如何分担运动 |
| 灯头位置策略 | **拖位置时锁定光束世界方向** | 每次都照桌面、保持腕相对角 | 锁定世界方向会让 q1/q2/q3 都动，符合“拖它，改变三个关节”；腕环可单独改朝向；不会把某个朝向硬编码成产品语义 |
| 实际姿态 | **ghost 线框/半透明** | 只显示目标、不显示实际 | 舵机有速度/背隙/滞后；不显示实际就会把“模型到了”误当成“真机到了” |
| 视觉 | **深色舞台 + 暖橙灯** | 沿用门户的暖纸底 | 3D 需要对比和光；门户仍是入口，进入孪生页后切换到“舞台”模式 |

## 4. 体验

### 4.1 进入与准备

门户新增应用卡：**A1 · 3D 孪生**（标注“09 固件 · 需三关节已标定”）。
打开 `web/twin.html`，默认不自动连接、不自动上力。

连接后先过门禁，六项全绿才允许拖：

1. `HELLO` 成功，`features` 含 `state,stream,motion,cal,limits`；
2. 三关节全部在线（`online=7`）；
3. 三关节标定有效（`CAL STATUS valid=1`，`cal=7`）；
4. 力矩三关节都开（`torque=7`）；
5. `mode=READY`（不是 `CAL/FAULT/ESTOP`）；
6. `STATE` 新鲜（`age` 合理），当前实测 q 都在 safe 区间内；`LIMITS` 三行都 `valid=1` 且 `wrap=0`
   （跨 0 的行程不能由 ST3215 默认角度模式执行，先回标定台 `CAL SPLIT`）。

任何一项不满足：画布只做展示，拖拽被禁用，显示缺哪一项，并给“打开 09 标定台”的链接。
门禁通过后先看 ghost 与实物是否同向；如果模型整体偏 90°，不要拖，先核对
`model_ref_q` / `head.mount_deg`（见 §6.1、§6.6）。
力矩没开时提供**显式**“上力（保持当前姿态）”按钮；不自动上力。该按钮只在三关节在线且标定有效时可用，
否则去标定台处理。孪生页**不放卸力**：卸力/示教会让重臂掉，仍回 09 标定台做。

### 4.2 拖灯头（位置 IK）

- 鼠标/手指按在灯罩（或灯罩上的大号透明拾取球）上，进入“拖灯头”。
- 指针射线与**手臂平面**求交，得到灯头中心目标 `P`。
- 拖动开始时，以**实体模型当前目标**的光束世界方向锁定为 `ψ_lock`；拖动过程中保持这个方向
  （不用可能滞后的实测方向）。腕关节因此会随 q1/q2 自动补偿——拖位置时三个关节都会动。
- `P` 与 `ψ_lock` 一起做 IK，得到 q1/q2/q3；三个 q 都必须在 safe 内才发 `POSE`。
- **腕到限位**：q3 被夹到 safe 边界时，保持灯头中心 `P`，允许光束偏离 `ψ_lock`，
  显示“腕到限位，灯头已倾斜”；不硬顶、不静默忽略。
- **不可达**：目标点在安全 workspace 外时，沿“上一个有效点 → 指针点”二分找边界，
  模型停在边界，指针处显示红色不可达标记；只发边界内的目标，绝不把越界目标发给固件。
- 指针按住不动也继续以 20 Hz 重发同一个 `POSE`，避免 300 ms `LinkLost`。
- **松手 = `STOP`**。350 ms 后把实体模型的目标 q 对齐到最新实测 q，避免“模型停在前面、真机停在后面”的长期错觉。
  松手后真机停在实际位置，不会继续追最后的目标；若 350 ms 内又按下，取消对齐，从实体模型当前目标继续。

### 4.3 抓关节（单关节 FK）

三个关节各有一个可见的金属环/透明拾取环：肩、肘、腕。

- 按住某个环，指针绕该关节轴的角度变化量直接加到该关节的 q 上；其余关节保持。
- q 夹在 safe 区间内；到限位时环变色并显示数值，不越过。
- 拖肩/肘时下游连杆跟着 FK 走；拖腕环时只有灯头俯仰变化。
- 抓关节同样以 20 Hz 发 `POSE`；松手 `STOP`。
- 灯头拖拽和关节拖拽互斥；拖动期间 `OrbitControls.enabled=false`。

### 4.4 相机

- 空处拖动 = 环绕；滚轮/双指 = 缩放；右键/双指平移默认关闭，避免误移目标。
- 预设：**等距/3/4（默认）**、**正视**（正对手臂平面，可拖）、**侧视**（沿手臂平面，只看不拖）；
  **近景灯头**、**全景**本轮未做（见 §14）。
- 不硬限相机方位角；拖拽开始时检查指针射线与平面法线的夹角，近乎侧切就拒绝开始并提示
  “请转到正视（侧视不可拖）”，避免平面求交飞点。M4 已按此实施。
- 拖模型时禁用环绕；松手恢复。`R` 回默认视角。

### 4.5 状态与反馈

界面只保留四块信息，不堆仪表盘：

```text
┌──────────────────────────────────────────────────────┐
│ LT100 · A1 3D 孪生      [连接] [上力] [STOP]          │
│ ┌──────────┐                              ┌────────┐ │
│ │ q1 肩    │         3D 台灯               │ 目标   │ │
│ │ q2 肘    │         实体=目标             │ x,y mm │ │
│ │ q3 腕    │         线框=实际             │ 误差   │ │
│ │ safe 条  │         光锥=实际             │ 朝向   │ │
│ └──────────┘                              └────────┘ │
│  拖灯头=位置/锁朝向   拖关节环=单关节    Esc=STOP      │
└──────────────────────────────────────────────────────┘
```

- 左上：连接、模式、电压、状态年龄（`age`）；
- 左侧：三关节卡（目标 q / 实测 q / safe 条 / 限位色）；
- 右上：灯头目标 `x,y`（mm）、目标 vs 实际灯头距离（mm）、光束方向角；
- 底部：操作提示 + `STOP`（红色，始终可见）+ `Esc` 提示。

模型语义：

- **实体模型** = 网页当前目标（已通过 safe 检查；至少是最近一次发出去的 q，两次 POSE 间可做显示插值）；
  指针的原始目标若被边界/限位/突变限制裁剪，只在指针处画标记，不把未发送的值画成模型；
- **ghost** = `STATE.q` 换算出的实测姿态，细线框/半透明冷色；
- 目标灯头与 ghost 灯头之间画一条误差线，长度即毫米误差；
- 光锥/桌面光斑按 **ghost（实际）** 姿态计算，并标“模拟光斑”；不把模型预测说成传感器。
- 不显示假的力矩/电流条；`load` 只作为原始百分比，若要显示必须标“不是力矩”。

### 4.6 移动端

- 单指空处 = 环绕；单指模型 = 拖手臂；双指 = 缩放；不做双指平移。
- 关节卡收进底部抽屉；`STOP` 固定悬浮在右下。
- 视角按钮在“环绕/操作”之间切换，避免单指既要转视角又要拖模型。
- 390 px 宽度下无横向滚动；画布至少保留 55% 高度。

### 4.7 明确不做

- 不做 2D 可拖目标小窗；不做“拖一个点，模型跟着”的替代交互。
- 不做自由 6DOF 拖拽；手臂永远在同一个平面内。
- 不做底座 yaw 滑杆当电机轴；底座朝向只做显示输入，不产生运动。

## 5. 3D 场景与模型

### 5.1 坐标与尺寸

- 原点：底座中心在桌面上的投影；`+Y` 向上；手臂平面为 `X-Y`，平面法线 `+Z`。
- 单位：毫米（`machine.json` 与场景一致）；相机近远平面按毫米设置。
- 肩轴高度 `shoulder_height`（约 80 mm，需实测）；底座半径、连杆宽度等只影响外观。
- 底座 yaw：`base.yaw_deg` 只旋转整个模型（含光锥/桌面光斑），不改变 q、IK 或安全判断；
  默认 0，手动输入以匹配实物，不假装有编码器。

### 5.2 参数化模型

按 `l1=180, l2=180, l3=90` 和 `hardware/photos/` 搭，不导入 CAD：

| 部件 | 做法 | 关键尺寸 |
|---|---|---|
| 底座 | 圆柱 + 转台 + 手摇柄 | 直径约 170、高约 55；手柄橙色 |
| 肩/肘/腕舵机 | 黑色圆角盒 + 银色舵盘 + U 支架 | ST3215 约 45×25×35 |
| L1/L2 | 橙色圆角扁条，带减重槽/孔 | 轴心距 180，宽约 32，厚约 12 |
| 灯头支架 | 黑色/橙色小支架，连腕轴 | 腕轴到灯罩中心 `l3=90` |
| 灯罩 | `LatheGeometry` 橙色圆锥/碗 | 开口直径约 100，深约 65 |
| LED 环 | `TorusGeometry` + 自发光 | 内圈暖白，低亮度 |
| 线缆 | `CatmullRomCurve3` + `TubeGeometry` | 关节处留服务弯 |
| 桌面 | 大平面 + 轻微粗糙度 | 接收阴影和光斑 |

实现细节：

- 用 `Shape` + `ExtrudeGeometry` 做圆角扁条，不额外引入 `RoundedBoxGeometry`。
- 层级：`baseYaw → shoulder → upperArm → elbow → forearm → wrist → head`；
  每个关节组绕本地 Z 轴旋转 q；`head` 组内再按 `head.mount_deg` 旋转灯罩。
- 拾取代理：灯罩外一个透明球（半径约 70），三个关节各一个透明环（管径约 18）；
  代理不写深度、不参与可见渲染，只参与 raycast。
- 高亮：hover 时环变亮/灯罩描边；拖动时保持高亮，松手恢复。
- 以后若拿到整臂 GLB/STEP，`model.mjs` 可以换成加载网格并绑到同一组关节组；
  IK/transport/安全层不变，参数化模型留作离线 fallback。

### 5.3 材质、灯光、桌面

- 材质：橙色塑料 `roughness≈0.55`；黑色舵机 `roughness≈0.4`；银色舵盘 `metalness≈0.9`；
  灯罩内侧暖白；LED 环 `emissive`。
- 主光：一盏带阴影的平行光/聚光，1024 阴影贴图；环境光用 `RoomEnvironment` + PMREM（本地 vendor）。
- 灯头光：`SpotLight`（不投影，避免第二个阴影贴图）+ 半透明锥体 + 桌面径向渐变光斑；
  光斑位置由实际光束与桌面 `y=0` 求交，方向朝上/平行时隐藏。
- 色调映射 `ACESFilmicToneMapping`，`outputColorSpace = SRGBColorSpace`；
  bloom 只在“高画质”档开启，阈值高，只让 LED 环发光，不让整屏发灰。
- 桌面/背景用深灰暖色，不抢橙色；底座下方加一张软接触阴影贴图，避免“浮空”。

### 5.4 性能

- 目标：桌面 60 fps、移动 30 fps；draw call < 100，三角面 < 20 万。
- `devicePixelRatio` 上限 2；移动/低画质档上限 1.5，关闭 bloom 和灯头阴影。
- 页面隐藏时暂停渲染；`ResizeObserver` 处理尺寸；不每帧创建几何/材质。
- 无 CDN、无网络字体；Three.js 本地 vendored，版本在实现时锁定并记录。

## 6. 运动学与坐标映射

### 6.1 两套关节角（必须先讲清）

固件的 `q` 是**标定坐标**：参考姿态由 `CAL REF` 记录为 `zero_q`，不同机器可以不同。
模型的是**手臂平面坐标**：`qModel1=90°` 表示上臂竖直向上。两者不能混用。

```
qModel_i = model_ref_q_i + (qFw_i - cal.zeroQ_i)
qFw_i    = cal.zeroQ_i    + (qModel_i - model_ref_q_i)
```

- `model_ref_q`：实物参考姿态在模型里的角度。标准参考姿态（上臂竖直向上、肘伸直、灯头朝正前方）
  为 `[90, 0, 0]`；写在 `machine.json`。
- `cal.zeroQ`：`CAL STATUS` 返回的每关节零点 q，**运行时以它为准**，不以文档/默认值为准。
- 当前实板标定页默认 `q=0` 记录零点，所以 `cal.zeroQ=[0,0,0]`；
  于是 `qModel1 = qFw1 + 90°`。这不是 bug，是两套坐标的正常换算。
  若某台机器用 `CAL REF 1 90` 标定，则 `zeroQ1=90`，`qModel1=qFw1`；同一套公式都成立。
- safe 区间同样换算：以 `LIMITS` 返回的 safe raw 为准，用 `rawToQ` 换成 qFw，再逐端点换成模型 q 并排序；
  `safeQRange(cal)` 只做一致性校验，两者不一致时提示并以 `LIMITS` 为准。
- **所有 POSE 发出前必须换回 qFw**；页面内部、IK、关节卡、模型都用 qModel。

连接时若 `CAL STATUS.zeroQ` 与 `machine.json.reference_pose.cal_q` 不一致，只提示、不拦截：
`zeroQ` 是这台机器的真实记录，`cal_q` 只是装配说明。

### 6.2 FK

```
θ1 = qModel1
θ2 = qModel1 + qModel2
θ3 = qModel1 + qModel2 + qModel3

W  = (l1·cosθ1 + l2·cosθ2,  h + l1·sinθ1 + l2·sinθ2)   // 腕轴
P  = W + l3·(cosθ3, sinθ3)                              // 灯罩中心（沿灯头支架）
ψ  = θ3 + head.mount_deg                                // 光束方向
```

- `W` 是腕轴；`P` 是灯罩中心；`ψ` 是灯罩开口朝向。
- `head.mount_deg` 是灯罩相对灯头支架的固定安装角；参考姿态“灯头朝正前方、手臂竖直向上”
  对应 `mount≈-90°`。不同装配/照片可能有差异，必须用实物对一次，见 §6.6。

### 6.3 拖灯头的 IK

输入：目标灯罩中心 `P`、锁定光束方向 `ψ_lock`。

```
θ3 = ψ_lock - head.mount_deg
W  = P - l3·(cosθ3, sinθ3) - (0, h)      // 转到肩轴局部坐标
r² = Wx² + Wy²
c2 = (r² - l1² - l2²) / (2·l1·l2)
```

- `c2` 不在 `[-1,1]`：不可达，走边界回退。
- `qModel2 = ±acos(c2)`：两解。优先选**离当前 q2 更近**的一支；若该支的 q1/q2/q3 有越界，
  试另一支；两支都越界 = 不可达。A1 不提供手动“换肘”，A2 再加。
- `qModel1 = atan2(Wy, Wx) - atan2(l2·sin q2, l1 + l2·cos q2)`。
- `qModel3 = θ3 - (qModel1 + qModel2)`。
- 三个 qModel 都必须在 safe 内；否则按“腕限位”或“不可达”处理。

**腕限位回退**（保持 `P`，允许光束偏）：

1. 把 `qModel3` 夹到 safe 边界；
2. `θ3' = qModel1 + qModel2 + qModel3_clamped`；
3. `W' = P - l3·(cosθ3', sinθ3')`，用 `W'` 重解 q1/q2（q3 固定）；
4. 再检查 q1/q2；通过就发，灯头会倾斜；不通过才算不可达。

**边界回退**：从“上一个有效 P”到“指针 P”做 12–16 次二分，取最后一个三 q 都 safe 的点；
模型停在那里，指针画红圈。绝不把越界目标发给固件。

### 6.4 抓关节

- 记录按下时的 `qStart` 和指针相对关节轴的角度 `aStart`（手臂平面内 `atan2`）。
- 移动时 `delta = wrap(aNow - aStart)`（归一化到 `[-180,180]`），`q = clamp(qStart + delta, safe)`。
- 肩/肘/腕分别只改 q1/q2/q3；其余 q 不变；FK 更新下游。
- 角度跨越 ±180° 时用最短角差，不能出现“从 +179 跳到 -179 变成转 358°”。

### 6.5 拖拽平面与相机约束

- 所有拖拽都在手臂平面 `Z=0` 内求交；`Raycaster.ray.intersectPlane`。
- 指针射线与平面夹角太小时求交点会飞；拖拽开始时检查 `|dot(ray.dir, plane.normal)|`，
  小于 0.2 就提示“请转到正视（侧视不可拖）”并拒绝开始拖拽。相机本身不做方位角硬限制。
- 拖拽期间禁用 OrbitControls，避免同一指针既转相机又拖手臂。

### 6.6 `machine.json`（主机几何，不是固件配置）

放在 `web/arm/machine.json`，由静态服务器提供：

```json
{
  "schema": 1,
  "id": "lt100",
  "units": "mm",
  "links": { "l1": 180, "l2": 180, "l3": 90 },
  "base": { "shoulder_height": 80, "radius": 85, "yaw_deg": 0 },
  "joints": [
    { "id": 1, "role": "shoulder", "model_ref_q": 90 },
    { "id": 2, "role": "elbow", "model_ref_q": 0 },
    { "id": 3, "role": "wrist", "model_ref_q": 0 }
  ],
  "head": { "mount_deg": -90, "shade_radius": 50, "shade_depth": 65 },
  "reference_pose": {
    "description": "上臂竖直向上、肘伸直、灯头朝正前方",
    "cal_q": [0, 0, 0]
  },
  "motion": { "speed_deg_s": 25, "acc": 20, "pose_hz": 20 }
}
```

- `cal_q` 只是装配说明；运行时 safe/零点以 `CAL STATUS` 为准。
- `mount_deg` 是唯一需要“看实物对一次”的模型参数：
  把实物摆到参考姿态，看灯头实际朝向；若灯头朝正前方而手臂向上，取 `-90°`；
  若灯罩轴与灯头支架同向，取 `0°`。模型和 IK 共用这个值，不能只改渲染不改 IK。
- `l1/l2/l3` 当前是文档值，实施时用卷尺量轴心距；量完写回本文件，不写死进代码。
- 不把 `soft_limit` 写进 `machine.json` 当第二套安全源；safe 只来自标定。

## 7. 架构与数据流

### 7.1 文件

```text
web/
├── twin.html                 页面骨架
├── twin.css                  深色舞台样式；复用现有字体/按钮语汇
├── twin.js                   入口：装配 UI、连接、状态机
├── arm/
│   ├── machine.json          几何/参考姿态/动作参数
│   ├── machine.mjs           加载配置；qFw ↔ qModel；safe 区间
│   ├── kinematics.mjs        纯 FK/IK/边界/限位；无 DOM
│   ├── scene.mjs             渲染器、相机、灯光、resize、渲染循环
│   ├── model.mjs             参数化模型、ghost、光锥、拾取代理
│   ├── interaction.mjs       射线、拖灯头、拖关节、边界回退
│   ├── transport.mjs         WebSocket/串口桥；HELLO/STATE/CAL/LIMITS/POSE/STOP
│   ├── mock.mjs              ?mock=1 的假固件；不接硬件
│   └── ui.mjs                侧栏/状态/错误/按钮
└── vendor/three/             锁版本的 three.module.js + OrbitControls + RoomEnvironment
```

复用 `web/lt100-protocol.mjs` 的解析/命令构造（`parseState`、`parseCalLine`、
`parseLimitsLine`、`rawToQ`、`safeQRange`、`poseCommand`、`commands.stop`），不复制协议。
Three.js 的 examples 模块用裸 `three` import；`twin.html` 用 import map 指到
`vendor/three/three.module.js`，尽量不改 vendor 文件，版本和许可证一起记录。

### 7.2 数据流

```text
pointer
  → interaction（平面求交 / 关节角差）
  → kinematics（FK/IK + safe 检查 + 边界回退）
  → machine.toFwQ（qModel → qFw）
  → transport（20 Hz POSE，seq++）
  → 固件（限位/速度/失联；最终权威）
  → STATE 10 Hz
  → machine.toModelQ
  → ghost / 关节卡 / 误差 / 光斑
```

目标模型在本地 60 fps 更新；`POSE` 只按 20 Hz 发；两次 `POSE` 之间只做显示插值，不改变目标值。
`STATE` 10 Hz 用时间戳插值到 ghost，但数值仍来自 `STATE.q`，不用目标值冒充实测。

### 7.3 协议

| 命令 | 用途 | 频率/条件 |
|---|---|---|
| `HELLO` | 协议/功能位 | 连接一次 |
| `STREAM ON` | 打开 10 Hz `STATE` | 连接后 |
| `STATE` | 主动查一次 | 连接、上力后、重连 |
| `CAL STATUS` | 读 `zeroQ`/valid/端点 | 连接、重连 |
| `LIMITS` | 读 raw safe | 连接、重连 |
| `POSE seq q speed acc` | 三关节目标 | 拖动期间 20 Hz；按住不动也重发 |
| `STOP` | 松手/失焦/报错/退出 | 立即 |
| `TORQUE all ON` | 显式上力 | 用户点按钮，不自动；卸力回标定台 |

- `POSE` 不逐帧 ACK；用 `STATE.seq` 判断最近接受的序号。若连续多帧 `seq` 不前进，
  显示“目标未被接受”，停止拖拽并查 `ERR`。
- 固件 `MOTION` 中 300 ms 没有新 `POSE` 会回 `READY` 并报 `ERR 17`；拖动期间必须持续发。
- 松手时先停掉 20 Hz 计时器并清拖动状态，再发 `STOP`；不要在 `STOP` 后补发最后一个 `POSE`，
  否则会重新进入 `MOTION`。也不能只停止发送，否则固件按失联处理。
- **拖动期间新到的** `ERR` 一律停止拖拽、显示 code/msg/joint、不自动重试；拖动开始前已存在的
  遗留 `ERR`（重连后串口缓冲里常见的 `ERR 17`）只显示，不拦新拖动。`ERR 10` 说明网页 safe
  判断与固件不一致，记日志并回标定台核对。

### 7.4 传输与单客户端

- 主路径：`ws://127.0.0.1:8771/serial`，本机串口桥。
- 桥同一时间只服务一个页面：连接超时/`HELLO` 超时时提示“先关闭 09 标定台/其他 LT100 标签”。
- Web Serial 只做手动回退，并在按钮上写明“打开串口可能让板子复位一次”；不自动切。
- `pagehide` / `visibilitychange` / `blur` / `pointercancel` 都发 `STOP`；
  `pagehide` 或桥断开时关闭连接；回来重新过门禁，不自动续拖。
- 桥/串口断开：立即禁用拖拽，显示原因；不把“最后目标”当成“已到位”。

### 7.5 Mock

- `twin.html?mock=1&auto`：不连硬件，模拟三关节已标定、safe、10 Hz STATE。
- Mock 的 `POSE` 让模型按速度逼近目标，并回 `STATE`；用于 UI/交互/截图/自动化 QA。
- Mock 不证明真机跟随、不证明标定、不证明失联；实板验收另算。

## 8. 安全

### 8.1 门禁（缺一不可）

- 三关节在线、标定有效、力矩开、`mode=READY`、实测 q 在 safe 内、`STATE` 新鲜（`age` 合理）。
- 页面 safe 判断只是**预检**；固件仍是最终权威。任何 `ERR 10` 都停。
- 未标定/离线/力矩关/FAULT/ESTOP/CAL：只读展示，不能拖。

### 8.2 运动

- 默认 `speed=25 °/s`、`acc=20`；不在拖动中动态改速度。
- 每个目标先过三 q safe；腕限位只夹 q3，并保持灯头中心；不可达只到边界。
  运动目标在 safe 边界再内缩 2 tick（约 0.18°），避免 q→raw 四舍五入后落到边界外触发 `ERR 10`；
  界面显示的 safe 区间仍是真实边界。
- 不静默把越界目标改成边界；边界是网页显式计算并显示的结果，固件仍会再检查。
  实体模型只显示最终会发出的 q；被裁剪的指针原始目标只做标记，避免“模型到了、其实没发”。
- 目标突变限制：每次 20 Hz `POSE` 前，若 IK 解与上一个已发目标的 q 差超过 25°，沿最短角差
  截到 25° 以内再发，避免双解/边界切换造成大跳；下一次 POSE 继续追。
- 拖动时如果实测 q 掉出 safe（手碰/丢步），立即 `STOP`，要求回标定台检查。

### 8.3 停止

- 松手、`pointercancel`、`blur`、标签隐藏、页面卸载、桥断开、`ERR`、`Esc`、`STOP` 按钮：
  全部发 `STOP`（能发的话）并清拖动状态。`STOP` 立即发出；固件把当前 raw 写回目标，
  舵机按 hold 速度减速，不是瞬间抱死。
- `STOP` 后不自动恢复；下一次拖动重新从当前目标开始，重新过门禁。
- 首次实板测试必须有人扶住手臂；烧录会复位/卸力，先扶住再烧。

### 8.4 不做

- 不在孪生页写 `CAL`、`ID`、`RAW`；不改 NVS。
- 不自动 `TORQUE ON`；不在孪生页做卸力/示教；不在 `CAL` 模式下发 `POSE`。
- 不把 `load` 当力矩传感器；不把模拟光斑当实测照度。
- 不在标定台开着时抢串口桥。

## 9. 测试与验收

### 9.1 单元测试（`platform/tests/web/kinematics.test.mjs`）

- FK 已知姿态：`qModel=[90,0,0]`、`l1=l2=180,l3=90`，检查腕/灯罩坐标。
- FK→IK 往返：在 safe 网格内随机/采样 q，`P=FK(q)`，`ψ=ψ(q)`，IK 回到同一支，误差 < 0.1°。
- 双解：同一 P 的 q2 正负两支都存在；选择离当前 q2 近的一支。
- 不可达：`r > l1+l2` 返回不可达，不返回伪造角度。
- 腕限位：q3 超 safe 时保持 P、q3 夹紧、光束偏移，结果三 q 仍 safe。
- 边界回退：从有效点到不可达点，返回最后一个 safe 点。
- 坐标映射：`zeroQ=0, model_ref_q1=90` 与 `zeroQ1=90, model_ref_q1=90` 两种都正确；
  safe 区间端点换算后排序正确。
- 关节差角：+179° → -179° 的 delta 是 +2°，不是 -358°。
- `machine.json` 校验：三关节、正长度、`mount_deg` 有限。

运行：`node --test platform/tests/web/*.test.mjs`（现有协议测试同目录）。

### 9.2 Mock/浏览器 QA

- `twin.html?mock=1&auto` 加载无 console exception。
- CDP 模拟拖灯头：目标变化、`POSE` 计数 > 0、松手后收到 `STOP`。
- 模拟抓 q1/q2/q3：只有对应关节变化；到 safe 边界夹住。
- 不可达：模型停在边界，红色标记出现，没有越界 `POSE`。
- 门禁：mock 切未标定/力矩关/FAULT，拖拽禁用。
- 桌面 1440×900、移动 390×844 截图；无横向溢出、无遮挡 `STOP`。
- 证据落 `.local/`，每次运行单独日志/截图，文件名带动作和时间戳。

### 9.3 实板验收

1. 三关节已标定、在线、上力、READY；连接后 ghost 与实物姿态一致。
2. 拖灯头 100 mm：真机朝同一方向移动；目标与 ghost 的毫米误差可见；松手发 `STOP` 后按 hold 速度停住。
3. 抓肩/肘/腕：只有对应关节动；到 safe 边界停；下游 FK 正确。
4. 腕限位：把 q3 拖到边界，灯头倾斜、目标点保持、页面提示；无 `ERR 10`。
5. 不可达：拖出工作空间，模型停边界，红色标记；串口无越界 `POSE`。
6. 失联：拖动中关闭标签/拔桥，固件 300 ms 回 READY/`ERR 17`，不继续跑。
7. 力矩关/未标定/离线：拖拽禁用；不自动上力。
8. `zeroQ` 变体：用 mock 验 `zeroQ=90`；实板当前是 `zeroQ=0`，记录实际映射。
9. 连续 10 分钟拖动/停止循环：无复位、无掉线、`age` 正常、无累积错误。
10. 证据：串口日志、STATE 采样、截图、测试命令与退出码放 `.local/`，不只贴对话。

### 9.4 验收口径

- “跟随”指真机按 25 °/s 向目标移动，lag 由 ghost 显示；不承诺“模型到哪真机立刻到哪”。
- “通过”必须有实板日志/截图；mock 和模型预测只算软件证据。
- 任何一项门禁失败时仍有运动 = 不通过。
- 页面显示“实际”必须来自 `STATE.q`；用目标值冒充 = 不通过。

## 14. M5 实施偏差（记录）

- 相机预设实际为 **正视 / 侧视 / 等距**；近景灯头、全景未做。
- 没有 Web Serial 回退；主路径只有本机 WebSocket 串口桥，桥是单客户端。
- 关节环半径 24、管径 2.5，环面平行于手臂平面、局部 `z=+13`；拾取为环带
  `10 <= 距环心 <= radius + 10` mm，中心孔不触发。命中距离用环心沿当前视线投到
  世界 Z=0 平面（本机 yaw=0 时即手臂平面）的点，补偿 z 偏移；拖动角度仍围绕枢轴中心。
- 拖动开始前已在串口缓冲里的遗留 `ERR` 只显示、不拦新拖动；拖动期间新到达的
  `ERR` 才停。HUD 仅在最新 `STATE.err != 0` 时显示 `ERR` 文案。
- 连续把灯头拖到 safe 边界时，舵机跟随误差可能让实测 `q` 越过 safe 约 0.2°（目标已按
  2 tick 内缩）。页面按设计锁住拖动，并在门禁失败时给“打开 09 标定台”链接；
  回 09 端点测试/回位后可继续。
