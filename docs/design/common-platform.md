# LT100 公版（Common Platform）设计

- 状态：**v0.3 草案（2026-11-21 与 lt100_core 0.1.0 对齐）**
- 定位：LT100 所有上层应用共用的**机械 + 电气 + 固件 + 主机/Web + 测试**底座
- 一句话：**公版负责“安全地动、准确地读、稳定地连”，应用只负责“怎么用、怎么展示、怎么教”**
- 相关：[interactive-applications.md](interactive-applications.md)（应用清单）、[design.md](design.md)（产品设计）、[kinematics-and-force.md](../teach/kinematics-and-force.md)（运动学）

## 0. 教学是第一目标，不是工程的简化版

**教学不是“把产品功能砍掉”，而是有自己的一等质量属性。** 工程化照样要安全、可测、可复现；只是力气优先花在“学生能不能看见、摸到、测到、改到”上，而不是把每个产品级细节都做满。

### 0.1 教学的五条质量属性

1. **可观察**：raw、deg、限位、误差、电流、温度、光斑、模式都要能看见；不能是黑盒。
2. **可复现**：同一实验换人做、换天做，结果能对上；有复位、预设、mock、标定记录。
3. **可分解**：一次只讲一个概念；平面、光斑、限位、平衡、孪生可以分开做，也能合起来。
4. **可安全失败**：学生按错、标错、越界时，系统拒绝/停止/提示，而不是撞坏或夹手；没有硬限位时，这一条尤其重要。
5. **可延伸**：学生能在公版上继续加弹簧、硬限位、yaw 刻度、自己的应用；公版留钩子，不把路封死。

### 0.2 这台机器的硬件事实（已确认）

- **yaw 只能手动转**：三个舵机都在同一个竖直平面内，只做 pitch；没有 yaw 电机、没有 yaw 编码器。
- **没有弹簧/配重**：重力完全由舵机保持；肩关节电流/温度是真实的教学观察点，也是风险点。
- **没有机械硬限位**：软件标定出来的限位是当前**唯一**的保护；标定错、NVS 坏、未标定就动，都会直接撞结构。

### 0.3 教学神韵：四个一

1. **一个平面**：三关节共面，学生用纸和卷尺就能画完、量完。
2. **一条光斑线**：灯头 pitch 决定光斑在桌面上的位置；没有电机 yaw 时，光斑中心只沿一条线走。
3. **一个手动 yaw**：人转底座，把这条线扫到桌面的另一处；网页只能提示/记录，不能把它当电机轴。
4. **一个软件限位**：没有硬限位，标定就是安全；标定表、端点验证、余量是课程的核心，不是附录。

### 0.4 教学第一版：六件能讲透的事

1. 标定 + 限位 + 端点验证（安全底座）；
2. `POSE/STATE/STOP/TORQUE/PRESET/LED` 六个基础能力；
3. 2D 精确视图：平面、角度、光斑线、手动 yaw 提示；
4. 拖目标 → IK → 实物跟随（先 2D，3D 后置）；
5. host 测试 + mock + 真板验收；
6. 一份学生能读懂、能改的 `lt100_core`，不是重型框架。

**不阻塞第一版、但也不是“不重要”**：App manifest/插件隔离、CI、ADR 全套、协议兼容矩阵、OTA、WiFi、多机协同、完整安全认证——它们是学生项目或规模化时再加的层次，不是第一版的入口门槛。

### 0.5 每层都要有“可交作业”的产出

公版不只输出代码，还要输出学生能记录、能解释、能复现的东西：

- 标定表：raw 端点、`zero_q`、方向、margin、端点验证结果；
- 覆盖图：机构平面、桌面光斑线、手动 yaw 标记；
- 物理表：姿态 vs `load`/温度/电压；
- 误差表：目标 vs 实际、重复精度、背隙；
- 演示证据：串口日志、状态 CSV、照片/视频、应用说明。

没有这些产出，公版就只是“跑起来了”，不是“讲清楚了”。

| 公版能力 | 学生要交的东西 |
|---|---|
| 标定/限位 | 标定表 + 低速端点验证记录 |
| 手动 yaw | 桌面光斑线/覆盖图 + 底座标记 |
| FK/IK | 预测位置 vs 卷尺实测 |
| `load`/温度 | 姿态-负载/温度曲线 |
| 2D 孪生 | 目标 vs 实际、误差/背隙 |
| 安全 | 越界/离线/失联故障注入记录 |
| 光 | 光斑范围、扩散/眩光观察 |

## 1. 定义与边界

### 1.1 公版是什么

公版是一套**稳定、可测试、可版本化**的平台，不是某个具体应用：

- 上层应用：2D/3D 孪生、IK 游乐场、覆盖图、示教回放、光绘、影子剧场、物理仪表盘、灯光编排等。
- 公版提供：标定、限位、安全、三关节同步、状态回读、协议、传输、运动学、渲染适配、录制、测试。
- 应用不允许直接操作舵机、串口或 NVS；只调用公版 API。

### 1.2 公版不是什么

- 不是 6 轴/通用机器人框架；固定 **3R 平面臂 + 灯头 + 灯环 + OLED**。
- 不是云平台/微服务；全部离线、本地。
- 不是 OTA/多板集群/插件商店；v1 不做。
- 不是把微雪出厂固件改一改；出厂固件只做舵机调试/恢复。
- 不是“每个应用一份固件”；**一份固件核心 + 多个应用页面/脚本**。

### 1.3 目标与非目标

| 目标 | 非目标（v1） |
|---|---|
| 安全：软件标定/限位 + 端点验证 + 失联保护 | 力控/阻抗/碰撞检测（无力传感器） |
| 可靠：30 分钟连续运行、不掉线、不复位 | WiFi/OTA/多机协同 |
| 可测：host 测试 + mock + HIL | 6 轴/视觉/SLAM/抓取 |
| 可教：2D 精确视图、角度/误差可见 | 云端遥测/手机 App |
| 可扩展：应用通过 SDK 接入，不改固件 | 插件沙箱/远程代码 |
| 离线：无 CDN、无网络依赖 | 高显色 COB/照度闭环 |

## 2. 质量属性与验收口径

公版 v1 的“完成”不是“能动”，而是：

- **安全**：未标定拒绝运动；越界拒绝；300ms 失联保持；任一舵机离线进入 FAULT 并停止自动运动；当前无机械硬限位，**标定 + 低速端点验证是唯一限位**（硬限位列为改进项）。
- **实时**：`POSE` 20 Hz 连续 30 分钟；`STATE` 10 Hz；命令到状态可见的延迟可测；无长阻塞。
- **准确**：`deg ↔ raw` 往返误差 ≤1 个 raw tick；FK/IK 往返误差可量化；标定掉电不丢。
- **可靠**：30 分钟不重启、不掉串口、不出现总线死锁；异常有错误码。
- **可维护**：协议/标定 schema/应用 API 有版本；有 ADR、测试、变更记录。
- **可教**：2D 视图能显示连杆、角度、目标、实际、误差、可达区；学生能看懂。

## 3. 总体架构

```text
┌─────────────────────────────────────────────────────────────┐
│ 上层应用（Web / 脚本 / 课程）                                │
│  2D孪生 · 3D展示 · IK · 覆盖 · 示教 · 光绘 · 仪表盘          │
└───────────────────────────┬─────────────────────────────────┘
                            │ 只调用公版 SDK
┌───────────────────────────▼─────────────────────────────────┐
│ 公版主机 SDK（浏览器，ES Modules）                           │
│  Transport · Client · MachineModel · Kinematics · Recorder   │
│  Twin2D · Twin3D · AppHost · Logger                          │
└───────────────────────────┬─────────────────────────────────┘
                            │ WebSocket 桥 / Web Serial / Mock
┌───────────────────────────▼─────────────────────────────────┐
│ 公版固件核心（ESP32 / Arduino）                              │
│  Protocol · Calibration · Limits · Motion · Safety · State   │
│  Presets · Storage · HAL（ServoBus/Clock/Display/Led）       │
└───────────────────────────┬─────────────────────────────────┘
                            │ UART1 1Mbps
┌───────────────────────────▼─────────────────────────────────┐
│ 3×ST3215 + 24灯WS2812 + OLED + 12V/5V                        │
└─────────────────────────────────────────────────────────────┘
```

**职责分工（关键）：**

- **主机做规划**：IK、插值、轨迹、录制、UI、渲染。
- **固件做安全**：标定、限位、速度/加速度、同步写、失联、过温/掉压、故障。
- 网页可以“建议”一个目标，固件有权拒绝；网页永远不能绕过固件限位。
- 2D 是精确视图；3D 只是渲染器，不拥有第二套 IK。

### 3.1 物理层（公版的一部分）

机械和电气不是“外壳”，是可靠性的第一层。**先按现状写，不把改进项当既有能力：**

- **yaw**：底座只能手动转；三舵机共面，只做 pitch。手动 yaw 没有编码器，网页的 yaw 滑杆只是“提示/模型”，不是测量；实际角度靠底座标记/刻度/目测。
- **机械硬限位**：当前**没有**。软件标定/限位是唯一保护；加硬限位是学生改进项目，不是现状。
- **重力平衡**：当前**没有弹簧/配重**；重力由舵机保持。肩关节电流/温度必须监控；弹簧/配重是改进项目，不是“已具备”。
- **关节与走线**：对侧轴承（如结构允许）、舵盘螺丝防松、灯环线与舵机线分开、关节留 2–3cm 服务环、硅胶线。
- **底座**：灯头伸到最远不翻；底座配重、硅胶脚垫；灯头/扩散片固定可靠。
- **电源**：12V 5A；入口保险丝；12V/5V 共地；板载 5V 给灯环，**全局亮度 ≤40%**；连接器/线径按 3A 级留余量。
- **可触及断电**：电源开关/急停；调试时手扶手臂。没有硬件急停时，断电就是急停。
- **测量基线**：12V 空载/运动、5V 空载/灯环 40%、三舵机待机/运动/堵转、20 分钟温度。

这些不是“应用效果”，但应用要“稳定可靠”就必须先有它们；**没有硬限位/弹簧时，软件标定和电流/温度监控就是安全主线**。

## 4. 核心契约

### 4.1 关节与单位

- 关节：`1=肩`、`2=肘`、`3=腕`（ST3215 ID 1/2/3）。
- 应用层统一用**度**；固件内部保存 raw 与标定，负责换算。
- 关节角 `q1/q2/q3`：
  - `q1`：肩绝对角；
  - `q2`：肘相对角（伸直为 0）；
  - `q3`：腕相对角（灯头俯仰）。
- 连杆绝对角：`θ1=q1`、`θ2=q1+q2`、`θ3=q1+q2+q3`；灯头朝向 `ψ=θ3`。
- 固件不保存 `l1/l2/l3`；几何在主机 `machine.json`，固件只关心关节角/raw。

```json
{
  "id": "lt100",
  "links": { "l1": 180, "l2": 180, "l3": 90 },
  "joints": [ { "id": 1, "role": "shoulder" }, { "id": 2, "role": "elbow" }, { "id": 3, "role": "wrist" } ],
  "reference_pose": { "q": [90, 0, 0] },
  "leds": 26
}
```

> `machine.json` 是机械事实（可随结构版本变）；NVS 是这台机器自己的零位/方向/限位。两者不要混。

### 4.2 标定 schema（NVS，版本 1）

```text
cal_version=1
joint1: zero_raw=... zero_q=90.0 sign=+1|-1 min_raw=... max_raw=... margin=40
joint2: zero_raw=... zero_q=0.0  sign=+1|-1 ...
joint3: zero_raw=... zero_q=0.0  sign=+1|-1 ...
checksum=...
```

`zero_q` 是“标定参考姿态在模型里的关节角”，必须和参考姿态一起记录。换算：

```text
q_deg = zero_q + sign * (raw - zero_raw) * 360 / 4096
raw_target = zero_raw + sign * (q_deg - zero_q) * 4096 / 360
```

> 这一步很关键：参考姿态是“上臂竖直向上”时，模型里的 `q1` 可能是 90°，不是 0°。不能把 `raw_zero` 直接当模型零点，否则后面 FK/IK 全偏。参考姿态的模型角写在 `machine.json` 的 `reference_pose`，标定向导用它生成 `CAL REF` 的 `q_deg`。

约束：

- 保存要求 `min_raw < max_raw`；`max-min > 2*margin`；跨 0 的行程先用 `CAL SPLIT` 截断成一段（v1 不做多圈环形运动）。
- `zero_raw` 必须落在 `min_raw+margin .. max_raw-margin` 内；参考姿态本身必须是安全可达姿态，否则拒绝保存。
- 零位必须来自**可复现的机械姿态**（治具/标记姿态/底座刻度），不能每节课随手改。
- **没有机械硬限位**：标定出来的 `min_raw/max_raw` 是唯一保护。标定必须按“扶住 → 卸力 → 慢移到安全端点 → MARK → 慢移到另一端点 → MARK → 保存”的顺序，端点要留 `margin`，不能拿撞死点当端点。
- **标定后必须做低速端点验证**：手扶/随时断电，向 safe min/max 各走一次，确认不撞、不夹线、不超温；记录结果。验证不通过不允许应用运动。
- 未标定：`POSE` 拒绝；`TORQUE OFF`、`STOP`、`STATE` 仍可用。
- 标定编辑只在 `TORQUE OFF` 下进行；第一次 `CAL REF/DIR/MARK` 进入 `CAL` 模式。`CAL` 模式下 `POSE` 和 `TORQUE ON` 被拒绝；`CAL SAVE` 或 `CAL CLEAR` 退出。未保存的编辑掉电即丢。
- 标定写入前校验、写后回读；NVS 有 schema 版本和 checksum。
- 换舵盘/拆臂/换舵机后必须 `CAL CLEAR` 重标；旧标定不能“凑合用”。

### 4.3 状态快照

`STATE` 至少包含：

```text
seq, mode, online, cal, torque, err, age_ms, q[3], raw[3], load[3], cur[3], volt, temp[3]
```

- `mode`：`BOOT/UNCAL/CAL/READY/MOTION/FAULT/ESTOP`。
- `online`、`cal`、`torque`：每位一个关节，`0..7`。
- `q`：由当前反馈 `raw` 按标定换算的**实测角**，不是最后目标；离线或该关节未标定时给 0。
- `load`：`ReadLoad` 的输出电压百分比（0..1000，带符号），**不是电流**；`cur` 是原始电流寄存器值，不能直接当安培。
- `seq`：最近接受的 `POSE` 序号；主机可判断是否陈旧。
- `age_ms`：设备距上次反馈读取的时间，用于诊断。
- `volt`：0.1V；`temp`：°C。

### 4.4 错误模型

- 错误码稳定、可读，不静默钳位；越界就是拒绝，不是“悄悄改成边界”。
- 当前冻结：
  - `01` 未知命令；`02` 参数错误；`03` 范围错误；`05` 行过长
  - `06` 舵机离线；`07` 无 ACK；`08` 端点非法；`09` 未标定；`10` 超出安全区
  - `11` 模式不允许；`12` 忙；`13` 协议/版本不匹配；`14` 存储失败
  - `15` 过温；`16` 掉压；`17` 失联/看门狗；`18` 内部错误
- 错误包含 `code, seq, msg, joint?`；致命错误进 `FAULT`，可恢复错误返回后保持当前模式。

### 4.5 模式状态机

```text
BOOT → UNCAL（标定无效）或 READY
UNCAL/READY → CAL（CAL REF/DIR/MARK，需 TORQUE OFF）→ READY/UNCAL（CAL SAVE/CLEAR）
READY → MOTION → READY
任意 → FAULT（离线/过温/掉压/内部）
任意 → ESTOP（显式急停）
FAULT/ESTOP → READY（CLEAR，且条件恢复）
```

- `CAL` 是标定会话：不自动退出，`STOP` 也不退出；`CAL SAVE` / `CAL CLEAR` 才回到 `READY` / `UNCAL`；重启丢弃未保存编辑。
- **上电不主动发目标**；没有弹簧/配重/硬限位时，扭矩策略必须实测，不能默认“卸力”（卸力可能掉臂），也不能自动“上力”（可能突然顶住/移动）。默认做法是人先扶住，标定有效后再显式 `TORQUE ON` 并以当前位置保持。
- `STOP`：取消当前运动，保持最后目标（扭矩保持）。
- `TORQUE OFF`：卸力；只允许在标定/示教/人工确认时使用；手臂可能掉落。
- `ESTOP`：锁存，停止接受运动；清除需要 `CLEAR` 且条件安全。
- 任一舵机离线：**停止所有自动运动**，进 FAULT；不要让剩余关节继续“猜”姿态。

> 这与早期 `course-4h.md` 的“其余关节继续工作”不同。公版 v1 取更保守的策略：灯臂少一个支撑就可能掉，先停再人工处理；课程文档后续对齐。

## 5. 固件架构

### 5.1 模块

| 模块 | 职责 | 依赖 |
|---|---|---|
| `Hal` | `Clock`、`ServoBus`、`Storage`、`Display`、`Led` 接口 | 无 |
| `Protocol` | 行解析、命令分发、版本、错误 | Hal/Clock |
| `Calibration` | raw↔deg、schema、校验、NVS | Storage |
| `Limits` | 每关节 min/max/margin、速度/加速度 | Calibration |
| `Motion` | `SyncWritePosEx`、目标执行、STOP | Hal/ServoBus、Limits |
| `Safety` | 看门狗、失联、离线、过温、掉压、FAULT | Motion、State、Clock |
| `State` | 快照、序号、状态频率 | 所有 |
| `Presets` | 预设姿态、NVS | Storage |
| `App`（sketch） | 初始化、循环、板级适配 | 核心 |

> 0.1.0 的实现把 `Protocol/Calibration/Limits/Motion/Safety/State` 收在 `lt100::Core` 里，用 `ServoBus/Clock/Storage/Output` 四个纯虚接口隔离 Arduino；`Presets/Led` 尚未实现。这样先保证安全主线可测，应用接口再逐步长出来。

### 5.2 代码约束

- C++17；`enum class`；命名空间 `lt100`。
- 初始化后不动态分配；命令缓冲、状态、日志用固定数组。
- 热路径不用 `String`/`std::vector`；不用长 `delay()`；循环单任务，非阻塞。
- 纯逻辑（标定换算、限位、协议解析）不依赖 Arduino 类型，方便 host 测试。
- 错误用返回值/状态，不抛异常；不静默失败。
- 所有对外 API 有明确单位（deg/raw/ms/°C/V）。

### 5.3 启动与循环

```text
setup:
  HAL 初始化 → 串口 → 总线 → OLED/LED → 加载标定
  → 扫描舵机 → 状态 = UNCAL/READY → 不运动

loop:
  serial.poll() → core.handleLine()
  core.tick()         # 反馈读取、失联、状态流
  ui.tick()           # OLED/LED 非阻塞
```

- 总线超时 20ms；`STATE` 10Hz（仅 `STREAM ON`）；`POSE` 20–50Hz。
- `STATE` 命令可随时主动查询；周期状态默认关闭，避免串口被刷屏。
- 任务看门狗；单次循环目标 <10ms；禁止 >100ms 阻塞。
- 上电/复位原因、固件版本、协议版本进 `HELLO`。

### 5.4 安全策略

- **当前没有机械硬限位，软件限位就是第一道也是唯一一道**：标定验证、NVS checksum、未标定禁动、低速端点验证，一个都不能省。
- 机械硬限位是学生改进项目；做完之前，不要在任何文档/演示里说“有硬限位兜底”。
- **当前没有弹簧/配重**：肩关节持续保持电流会热；限制水平姿态停留，监控 `load`/温度/电压；弹簧/配重是改进项目，不是现状。
- 力矩/速度/加速度上限；过温降额/停止；掉压停止运动。
- 失联 300ms：停止接受新目标，保持最后目标；不自动卸力（卸力可能掉落）。
- 舵机离线：FAULT + 停止自动运动；`TORQUE OFF` 需人工确认。
- 存储失败：不允许运动（标定不可信）。
- 看门狗复位后：不自动恢复运动，等 `HELLO`/显式指令。

> 0.1.0 已接入速度/加速度上限、离线、失联、存储失败和端点校验；**力矩上限、过温、掉压尚未接入**，接线/实测后再补，不能把设计当已实现。

### 5.5 可观测性

- 对外：`STATE`（10Hz）、`ERR`（带 seq/joint）。
- 0.1.0 尚未实现 `EVT`/`STATS`；扭矩/模式变化先由 `STATE` 的位掩码和 `mode` 体现。
- 对内：固定大小的错误/事件环形缓冲；`STATS`（可选）输出循环时间、总线错误、最大温度、最低电压。
- 不在运动热路径逐帧打日志；日志写串口会拖慢循环，必要时降频/摘要。
- 主机侧 `Logger` 记录连接、HELLO、错误、状态摘要；测试证据落 `.local/` 或 `docs/validation/`。

## 6. 主机/Web SDK

### 6.1 模块

| 模块 | 职责 |
|---|---|
| `Transport` | 连接、发送、按行接收、关闭；WebSocket/Web Serial/Mock 适配 |
| `Client` | `HELLO`、`STATE` 订阅、`POSE`、`STOP`、`TORQUE`、`CAL`、`PRESET`；超时/重连 |
| `MachineModel` | 关节/连杆/灯头、标定结果、限位、工作空间；纯数据 |
| `Kinematics` | FK/IK、光斑/覆盖；纯函数，有单元测试 |
| `Recorder` | 轨迹 JSON（schema/version/时间戳）；录制/回放 |
| `Twin2D` | SVG/Canvas 精确视图：连杆、角度、目标/实际、误差、可达区 |
| `Twin3D` | Three.js 适配器；同一模型，不重复 IK |
| `AppHost` | 应用 manifest、生命周期、能力校验、错误边界、单运动应用 |
| `Logger` | 结构化日志、错误、证据 |

### 6.2 客户端规则

- 应用不直接 `new WebSocket()` / `navigator.serial`；只能通过 `Client`。
- 连接后先 `HELLO`，检查协议/固件/标定版本；不兼容只读/提示升级。
- `POSE` 是“最新目标覆盖”，不每帧等 ACK；`STATE.seq` 判断是否被接受。
- 运动命令失败不自动重试；重连后不自动恢复运动，必须应用显式重新 arm。
- `STOP` 优先级最高；`TORQUE OFF` 需 UI 二次确认/手扶提示。
- 状态 10Hz；UI 可 60fps 插值，但显示“实际”必须来自 `STATE`。

### 6.3 传输

- v1 优先 **本机 WebSocket 串口桥**（`127.0.0.1:8771`），Web Serial 只做回退。
- 桥只监听 localhost + Origin 白名单；单客户端；页面切换时先断开。
- Mock 传输用于无硬件 UI/测试；与真实传输同一协议。
- WiFi/手机 v1 不做；以后单独设计鉴权、TLS/局域网策略。

### 6.4 2D/3D

- 2D 是精确视图：角度、连杆、目标、实际、误差、可达线/带；课堂用这个。
- 3D 是展示适配器：程序化几何（按 `l1/l2/l3`），桌面、灯头、光锥、轨道相机；不导入 STEP。
- 两者共享 `MachineModel` 和 `Kinematics`；禁止各写一套 IK。
- 3D 依赖本地化 Three.js；无 CDN；加载失败自动回退 2D。

## 7. 应用契约（App SDK）

> **教学第一版不做完整插件系统**：一个控制页 + 一套 SDK，规则是“应用不直连串口、同一时间一个运动页”。下面的 manifest/能力校验是多应用/规模化时的扩展，不阻塞教学。

### 7.1 Manifest

```json
{
  "id": "twin2d",
  "name": "2D 孪生",
  "version": "1.0.0",
  "api": 1,
  "protocol": 1,
  "capabilities": ["state", "motion", "led"],
  "safety": "planning-only"
}
```

- `capabilities`：`state/motion/led/oled/teach/presets`；运行时校验。
- `safety`：应用只能“规划”；固件是安全权威。
- 同一时刻只允许一个 `motion` 应用；`AppHost.activate()` 先停上一个。
- 应用必须处理 `FAULT/ESTOP/UNCAL`，不能假设“连接=可动”。

### 7.2 生命周期

```text
mount(host) → activate() → onState(state) → onTick(dt) → deactivate() → dispose()
```

- `activate`：申请能力、读取 machine/cal、建立 UI；不自动发运动。
- `deactivate`：发 `STOP`、停止定时器、释放视图。
- 应用异常被 `AppHost` 捕获，显示错误，不拖垮整个页面。
- 应用配置用 JSON；不从网络加载代码；不用 `eval`。

## 8. 协议（LT100P/1）

### 8.1 形式

- UTF-8 文本行，`\n` 结尾；单行 ≤128 字节；大小写不敏感（建议大写）。
- 命令：`VERB key=value ...`；事件：`STATE/ERR/EVT ... key=value`。
- 不用 JSON 做热路径；JSON 只用于主机侧配置/录制。
- 一行一条；解析失败回 `ERR code=02`；超长回 `ERR code=05` 并丢弃该行。

### 8.2 命令（v1 草案）

```text
HELLO
STATE
STREAM ON|OFF
POSE seq=<n> q=<q1>,<q2>,<q3> speed=<deg/s> acc=<0..254>
JOG seq=<n> id=<1..3> q=<deg> speed=<deg/s> acc=<0..254>
RAW id=<1..3> raw=<0..4095> speed=<deg/s> acc=<0..254>
STOP
ESTOP
TORQUE <id|all> ON|OFF
CAL STATUS
CAL REF <id> <q_deg>              # 当前姿态记为模型角 q_deg（含参考姿态偏移）
CAL DIR <id> +1|-1                # raw 增大时 q 的方向
CAL MARK <id> MIN|MAX             # 当前 raw 记为 raw 端点
CAL SPLIT <id> LOW|HIGH           # 跨 0 时保留 0..MAX 或 MIN..4095 一段
CAL SAVE
CAL CLEAR <id|all>
LIMITS
CLEAR
ID GET
ID SET <1..3>
```

- `POSE`：三关节目标，度；固件换算 raw、检查限位/模式/标定；最新覆盖。`speed` 为度/秒（1..52，默认 22），固件按 `speed*4096/360` 换成舵机刻度/秒；`acc` 是舵机加速度寄存器（0..254），不是物理 deg/s²。**流式命令**：进入 `MOTION` 后 300 ms 内没有新 `POSE` 会判 `LinkLost`；网页整机测试以 10 Hz 重发，到位或超时用 `STOP` 收尾。
- `JOG`：**单关节**目标，只要求该关节在线、标定有效、该关节扭矩已开；其余关节不受影响。一次性目标，不要求 20Hz 连续发送，也不会触发 POSE 的 300ms 失联错误。端点测试用它，所以单舵机标定完就能测试。
- `RAW`：**安装定位专用**。要求总线上恰好只有这一颗舵机、该关节没有标定记录（`calibrationJointValid` 为假）、该关节扭矩已开；直接写 0..4095 的 raw，**不经过 safe 区间**。一次性目标，语义同 JOG。已有标定记录的关节拒绝（`ERR 11`），避免绕过限位；装舵盘/对齿时由网页「配 ID」页使用。
- **行程跨 0**：raw 是单圈 0–4095。ST3215 默认角度模式（mode 0）把目标位置当作 0..4095 的绝对角度，按“目标 − 当前”的符号决定方向；跨 0 的目标会让它朝反方向走长路径，越过端点。安装时应先接标定工具扫行程，让 0 点落在机械行程外。已经装好且跨 0 时，两个 `CAL MARK` 照常记录（`min_raw > max_raw`），但 `CAL SAVE` 拒绝（`ERR 08`），必须先用 `CAL SPLIT <id> LOW|HIGH` 保留一段：`LOW` 保留 `0..max`，`HIGH` 保留 `min..4095`；只有含 `zero_raw`（且离接缝 ≥ margin）的一段可用，另一段不可达，接缝端不是机械端点。要完整支持跨 0 需改用多圈模式（mode 3，±7 圈；掉电圈数不保存），固件未实现。`rawToQ/qToRaw` 仍沿**标定弧**换算，非跨 0 的超过 180° 行程没有歧义。
- `STOP`：立即原地停住（把当前姿态写回目标，让舵机减速）；模式回 READY，仍可继续接命令；幂等。
- `ESTOP`：锁存急停；收到时立即读当前位置并写回作为目标，让**在途运动当场减速停住**，然后保持位置（扭矩保持）；不自动卸力；物理急停/断电另做。`CLEAR` 后才能恢复。
- `TORQUE OFF`：卸力；需人工确认；可能导致手臂掉落。任何时候都允许。
- `TORQUE ON`：已标定的关节必须在线且当前 raw 在标定行程内，否则拒绝并返回 `ERR 10`（关节被手挪出行程，先推回去）；通过后先把目标设为**当前姿态**再使能，防止上力瞬间跳到上一个残留目标。
- `STREAM ON|OFF`：打开/关闭 10Hz 周期 `STATE`；默认关闭，`STATE` 可随时主动查询。
- `CAL`：只在 `TORQUE OFF` 下操作；`CAL REF/DIR/MARK` 进入 `CAL` 模式，`CAL SAVE` / `CAL CLEAR` 退出；`CAL SAVE` 校验后写 NVS，部分标定会停在 `UNCAL`。两个 `CAL MARK` 的顺序随意：固件取两个端点之间**包含参考姿态**的那段弧作为行程，并把端点规范化成 `minRaw -> maxRaw`（沿 raw 增大方向）。**前提：参考姿态必须落在操作者想允许的行程内；若参考姿态在行程外，固件会改选包含它的补弧，标定仍会保存成功、显示有效，但实际行程是反的。** 几何上无法区分“人想允许的弧”和“包含参考姿态的弧”，这一点只能由操作者保证。**跨 0 的行程在 `CAL SAVE` 时会被拒绝**（`ERR 08`）：默认角度模式不能执行跨 0 的目标；两个 `MARK` 之后用 `CAL SPLIT <id> LOW|HIGH` 保留含 Z 的一段，另一段作废。已存在于 NVS 的跨 0 标定仍可读回检查，但不进入有效位、不能用于运动。
- `LIMITS`：输出每关节 raw 端点与含 margin 的 safe 区间。
- `ID GET` / `ID SET <1..3>`：读/改**当前唯一在线**舵机的 EEPROM ID。总线上多于一颗返回 `busy`，一颗都没有返回 `servo_offline`；写完自动读回验证。用于把出厂默认 ID1 的舵机分配成 肩=1 / 肘=2 / 腕=3。FAULT 下也可用，方便换舵机后先配 ID 再恢复。
- `CLEAR`：清除 FAULT/ESTOP；已标定时要求三舵机都在线，否则保持故障；非故障状态为幂等 no-op。
- **0.1.0 未实现**：`PRESET`、`LED`、`EVT`。复杂轨迹由主机发送；预设/灯效后续加。

### 8.3 事件

```text
HELLO protocol=1 fw=0.1.0 cal=1 features=state,stream,motion,jog,raw,cal,limits,id,split
STATE seq=42 mode=READY online=7 cal=7 torque=7 err=0 age=12 q=20.0,0.0,-10.0 raw=2276,2048,1934 load=100,100,100 cur=20,20,20 v=120 t=39,40,38
ERR code=10 seq=42 joint=0 msg=outside_safe
```

- `STATE` 10Hz（`STREAM ON` 时）；`seq` 为最近接受的 `POSE`；`ERR` 带 `seq` 便于对账。
- `mode` 有 `CAL`（标定会话），不要和 `UNCAL`（标定不完整）混用。
- `load` 是输出电压百分比，`cur` 是原始电流寄存器；两者都不是标定过的物理单位。
- 不为每帧 `POSE` 回 ACK，避免总线/串口被 ACK 淹没；以 `STATE` 为准。
- 版本不匹配：`HELLO` 仍返回，但运动命令回 `ERR 13`；主机提示升级。

### 8.4 超时与重连

- 主机命令超时 250ms；`STOP` 150ms；超时只报错，不盲目重发运动命令。
- 设备失联 300ms：停止接受新 `POSE`，保持最后目标；回 `ERR code=17 msg=link_lost`；不自动卸力。
- 重连：重新 `HELLO`/`STATE`；应用必须显式重新 arm；不自动续跑。
- 状态 `age` 超过 300ms，主机 UI 标记“数据陈旧”。

## 9. 测试与验证

### 9.1 测试金字塔

1. **纯逻辑单测**（host）：标定换算、限位、FK/IK 往返、协议解析、错误码。
2. **契约/黄金用例**：固定命令序列 → 固定响应/状态；防止协议漂移。
3. **Mock 集成**：无硬件跑 2D 双生、应用生命周期、错误路径。
4. **HIL**：pyserial/pytest 对真板；限位、失联、离线、NVS、30 分钟。
5. **E2E**：页面拖目标 → 实物跟随 → 状态回读。

### 9.2 关键用例

- 未标定：`POSE` 必须 `ERR 09`；`STOP` 可用。
- 越界：`POSE` 必须 `ERR 10`，舵机不动作。
- 标定端点验证：低速向 safe min/max 各走一次，不撞结构/不夹线；记录；失败则禁止应用运动。
- 手动 yaw：2D 覆盖图只做提示/标记，不把网页滑杆当角度测量；底座实际角度靠刻度/标记。
- 上电扭矩：人扶住；固件不自动发目标；卸力/上力行为实测并记录。
- 标定往返：`raw→deg→raw` 误差 ≤1 tick；掉电重启保持。
- 失联：停止发 `POSE` 300ms，保持最后目标，不突然卸力。
- 拔舵机：进 FAULT，停止自动运动；恢复后需 `CLEAR`。
- 过温/掉压：按配置降额/停止（台架模拟）。
- 30 分钟：20Hz `POSE` + 10Hz `STATE`，不重启、不掉线。
- 页面/桥：断线重连不反复复位板子；Origin 非本机被拒绝。
- 存储损坏：校验失败 → 拒绝运动，可恢复默认。

### 9.3 CI

- 固件：`arduino-cli compile`（固定 FQBN/库版本）+ 编译警告。
- Host C++：`pwsh platform/tests/host/run-tests.ps1`（MSVC vcvars64；构建并运行）。
- Host JS：`node --test`（JS 纯逻辑）。
- 静态：`node --check`、`git diff --check`、文档链接检查。
- 硬件测试不进公共 CI；用本地/实验室 runner，日志进 `.local/` 或 `docs/validation/`。

## 12. 关键决策（ADR 摘要）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| 1 | Arduino 框架 + 模块化 C++ core | ESP-IDF | 课程/IDE 已统一；core 可测试即可，不换生态 |
| 2 | 主机做 IK，固件只做安全/执行 | 固件做 IK | 迭代快、可视化/教学方便；固件保持小且可验证 |
| 3 | v1 文本行协议 | 二进制/JSON | 可读、可抓包、易教；115200/1Mbps 足够 |
| 4 | 出厂固件只做调试/恢复 | 直接改出厂固件 | 单舵机演示、无应用协议/安全/测试；不背架构债 |
| 5 | 2D 精确视图，3D 展示适配 | 只做 3D | 平面臂 2D 才精确；3D 是外壳，不能替代测量 |
| 6 | USB/本机 WebSocket 优先 | WiFi AP/手机 | 稳定、离线、安全；WiFi 后置 |
| 7 | 一份 core + 多应用页面 | 每个应用一份固件 | 共用安全/协议/标定；避免分叉 |
| 8 | 教学第一版：一个控制页 + SDK；manifest/多应用隔离后置 | 复杂插件系统 | 先保证能教；避免框架税 |
| 9 | 上电不主动发目标；扭矩策略实测 | 默认卸力/自动保持 | 无弹簧/硬限位，卸力会掉臂，自动上力可能突动；人工扶住 + 显式上力 |
| 10 | v1 不做 OTA/力控/6 轴 | — | YAGNI；先做可测的 3R 灯 |
| 11 | yaw 手动，v1 不电机化 | 加 yaw 电机/编码器 | 手动 yaw 本身就是课程；先把平面讲透 |
| 12 | 当前无弹簧/硬限位，作为改进项目 | 先补机构再教学 | 现状可教；软件标定是安全主线 |

## 13. 实施顺序

### Phase 0：契约与安全核心

- 冻结 `LT100P/1`、标定 schema、状态/错误码；
- `lt100_core` 骨架：协议、标定、限位、状态、安全；
- `POSE/STATE` + `SyncWritePosEx` + 失联；
- host 纯逻辑测试 + mock；
- 电源保险丝/走线/底座稳定同步做；机械硬限位作为学生改进项目，不阻塞教学。

**出口**：不接网页，脚本 20Hz 发 `POSE`、10Hz 读 `STATE` 30 分钟；未标定/越界/失联/端点验证用例通过。

**当前进度（2026-11-21）**：契约、`LT100Core`、`LT100Board`、host 测试、09 迁移和网页标定向导已落地；
出口里的 30 分钟真板 `POSE` 还没做——ID2/ID3 未接，只验证了单关节在线与 mock 流程。

### Phase 1：SDK + 2D 孪生

- `Transport/Client/MachineModel/Kinematics/Twin2D`；
- 标定向导 + 低速端点验证记录；
- 2D 拖目标、目标/实际、双解、覆盖线/手动 yaw 提示、ghost 误差；
- 一个控制页规则；manifest/多应用隔离后置。

**出口**：网页拖目标 → 实物跟随；误差可量化；断线重连不自动动。

### Phase 2：示教/预设/3D

- 示教记录/回放（host 录制，设备执行）；
- 预设/NVS、灯光编排；
- 3D 适配器；2D/3D 同一状态。

**出口**：一键预设、示教回放、3D 与实物同步。

### Phase 3：展示应用

- 光绘、影子剧场、目标游戏、物理仪表盘/重力与电流（弹簧/配重对比作为改进项）；
- 语音/手势/手机可选，最后做。

## 14. 风险与待确认

| 项 | 影响 | 现状/应对 |
|---|---|---|
| yaw 只能手动 | 光斑中心只沿一条线；覆盖靠人转底座 | 已确认；2D 视图用“手动 yaw 提示/标记”，不假装电机轴 |
| 无弹簧/配重 | 肩关节保持电流/发热；上电卸力会掉臂 | 已确认；监控 `load`/温度；弹簧/配重列为改进项目 |
| 无机械硬限位 | 软件限位是唯一保护；标定错就撞 | 已确认；标定 + 低速端点验证 + NVS 校验 + 未标定禁动是 P0 |
| `load` 单位 | 能否做力矩/电流实验 | 待确认 `ReadLoad` 定义/校准；先只做趋势，不标 A |
| 12V/5V 预算 | 三舵机+灯环+OLED 掉压 | 待实测峰值/线径/保险丝 |
| 内存/循环预算 | 20Hz+10Hz+OLED/LED 是否够 | 待实测 loop 时间/栈 |
| 桥单客户端 | 标定台/孪生页冲突 | 单页整合或扩多客户端 |
| 上电扭矩 | 无弹簧时卸力会掉，自动上力会突动 | 按“人扶 + 不自动发目标 + 显式上力”实测确定 |
| 3D 依赖 | 离线/性能 | Three.js 本地化/回退 2D |

**v1 明确不做**：WiFi/OTA、力控/阻抗、6 轴/视觉/抓取、云端、插件沙箱、多机协同。
