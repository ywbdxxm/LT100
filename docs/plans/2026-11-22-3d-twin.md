# LT100 A1 3D 孪生实施计划

> **状态：active（2026-11-22）**
> **规格：** [docs/design/3d-twin.md](../design/3d-twin.md)
> **分工：** Sisyphus 实现/调试；Atlas 设计/规划/审阅/调试。**提交权在 Atlas**，Sisyphus 不 commit。
> **For agentic workers:** 用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`
> 按任务逐步执行；每一步用 `- [ ]` 追踪。

**Goal:** 在浏览器里用 Three.js 直接拖 LT100 的 3D 模型（灯头位置 IK + 关节环 FK），
通过现有 `LT100P/1` 让实机以 20 Hz `POSE` 跟随，并用 ghost 显示 `STATE.q` 实际姿态。

**Architecture:** 纯 ES module + 本地 vendored Three.js，无 React/Vite/构建链。
`kinematics.mjs` 是纯函数层；`machine.mjs` 负责 qFw↔qModel/safe；`model.mjs`/`scene.mjs`
是渲染层；`transport.mjs` 只包 `lt100-protocol.mjs`；`interaction.mjs` 把指针变成安全 q。
固件不改，协议仍是 `HELLO/STATE/CAL STATUS/LIMITS/POSE/STOP/TORQUE`。

**Tech Stack:** Three.js（锁版本、本地 vendor）、原生 ES module、WebSocket 串口桥
`ws://127.0.0.1:8771/serial`、Node `node --test`、Chrome/CDP 截图/冒烟。

## Global Constraints

- 三关节 q 的**两套坐标**必须分开：`qFw`（`STATE.q`/`CAL STATUS.zeroQ`）与 `qModel`
  （模型平面角，`qModel1=90°` 为上臂竖直）。
  `qModel_i = model_ref_q_i + (qFw_i - zeroQ_i)`；发出 `POSE` 前必须换回 `qFw`。
- `safe` 以 `LIMITS` 的 safe raw 为准，用 `rawToQ` 换成 qFw；`LIMITS` 必须 `valid=1` 且 `wrap=0`。
- 网页只做预检；固件仍是最终权威。任何越界目标不得发 `POSE`；`ERR 10` 立即停。
- 拖动期间 20 Hz `POSE`；按住不动也重发。松手先停计时器并清拖动状态，再发 `STOP`；
  `STOP` 后不得再补发 `POSE`。
- 实体模型只显示最终会发出的 q；被边界/限位/突变裁剪的指针目标只做标记。
- Ghost 必须来自 `STATE.q`，不能用目标值冒充。
- 门禁：三关节在线、标定有效、力矩开、`mode=READY`、`STATE` 新鲜、实测 q 在 safe。
- 不修改固件、不写 `CAL/ID/RAW`、不自动 `TORQUE ON`、不在 `CAL` 模式发 `POSE`。
- 不在本计划里修改 `student-package/`；它是已构建的分发快照，M5 后另开打包任务。
- 同一文件单写者：Sisyphus 开始每个任务前先报文件清单；Atlas 审阅时不改正在写的文件。
- 真机运动/烧录必须有用户在场并扶住手臂；M1/M2 不需要真机。

## Review Focus

1. `zeroQ=0` 与 `zeroQ=90` 两种标定都必须把模型放在同一物理姿态；不能把 `qFw` 当 `qModel`。
2. `LIMITS` 的 safe 端点经 `rawToQ` 后顺序/边界正确；`wrap=1` 必须被门禁拒绝。
3. IK 双解、q3 限位回退、不可达边界回退都不能返回未检查的 q；不能静默越界。
4. 松手/`pointercancel`/`blur`/`pagehide` 的停止顺序：先停发，再 `STOP`；不能 `STOP` 后又发 POSE。
5. 实体模型与 ghost 的语义必须可分辨；任何“实际”显示只能来自 `STATE.q`。

## Task 2: 纯运动学 `kinematics.mjs`

**Files:**
- Create: `web/arm/kinematics.mjs`
- Test: `platform/tests/web/kinematics.test.mjs`

**Interfaces:**
- `fk(machine, qModel) -> { shoulder:{x,y}, elbow:{x,y}, wrist:{x,y}, lamp:{x,y}, theta:[number,number,number], psi }`
- `ikHead(machine, lampTarget, psiLock, currentQModel, safeRanges) -> {
    ok, qModel?, lamp?, psi?, reason?: "unreachable"|"safe"|"q3-clamped"|"branch"
  }`
- `clampJointDrag(machine, qStart, jointIndex, deltaDeg, safeRanges) -> { qModel, clamped }`
- `bisectSafeTarget(machine, fromLamp, toLamp, psiLock, currentQModel, safeRanges) -> { ok, lamp?, qModel? }`

**Rules:** 按设计 §6.3。灯头位置 `P`，锁 `ψ_lock`；`θ3=ψ_lock-mount`；
`W=P-l3·u(θ3)`；2R 余弦定理；q2 取离当前近的一支；q3 超 safe 时保持 P、夹 q3、重解 q1/q2；
不可达从上一个有效点二分 12–16 次。

- [ ] **Step 1: 写失败测试**：
  - FK 已知姿态 `[90,0,0]` 的腕/灯罩坐标。
  - FK→IK 往返：safe 网格采样，误差 <0.1°，同支。
  - 双解：选离当前 q2 近的一支。
  - `r > l1+l2` 不可达；不返回伪造角度。
  - q3 限位：保持 P、q3 夹紧、结果三 q safe。
  - 边界回退：有效点→不可达点返回最后一个 safe 点。
  - 关节差角 +179°→-179° 的 delta 为 +2°。
- [ ] **Step 2: 运行测试确认失败**。
- [ ] **Step 3: 实现纯函数**，不依赖 `machine.mjs` 以外的模块；角度单位统一为度。
- [ ] **Step 4: 运行测试通过**并跑全量 web tests。
- [ ] **Step 5: 停在这里交给 Atlas 审阅；Atlas 提交。**

**Acceptance:** 所有测试通过；任何返回的 qModel 都已在 safe 内，或明确 `ok:false`。
