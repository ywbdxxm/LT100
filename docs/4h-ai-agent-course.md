# LT100 四小时 AI Agent 课程设计

- 日期：2026-11-17
- 课程名：**4 小时：让 AI 给一台真实台灯写固件**
- 核心：学生不写语法，写**规格 + 约束 + 验收**；AI agent 写代码、编译、烧录、读串口；硬件是唯一的裁判
- 对象：中职/本科高年级/创客，2–3 人一个工位
- 规模：6 个工位（12–18 人），1 名主讲 + 1 名助教

---

## 1. 课程定位

传统嵌入式课：学生写代码 → 编译 → 烧录 → 调 bug。
这节课：**学生写清楚「要什么、不能碰什么、怎么算成功」→ AI 写代码 → 学生用硬件验证 → AI 根据证据修**。

```
学生：规格 / 约束 / 验收
  ↓
AI agent：读工程 → 改代码 → 编译 → 烧录 → 读串口
  ↓
硬件：舵机转不转、灯亮不亮、照度变不变
  ↓
学生：记录证据 → 判 PASS/FAIL → 让 AI 继续
```

**为什么用台灯**：它有机械、执行、传感、光学、通信，AI 的错会立刻变成可见的物理现象——舵机不动、灯不亮、照度不降、串口报错。这比「编译通过」诚实得多。

---

## 2. 学习目标

4 小时后，学生应该能：

1. 写一份 AI 能执行的**硬件契约**：引脚、ID、库、限位、安全规则。
2. 让 AI 在一个真实工程里完成「改代码 → 编译 → 烧录 → 读串口」的闭环。
3. 用**硬件证据**验收 AI 的输出，而不是「它说完成了」。
4. 识别 AI 在嵌入式里的五类常见错误：引脚冲突、阻塞延时、越界、未处理传感器失败、串口占用。
5. 用测试脚本驱动 AI 迭代，而不是靠聊天感觉。

不追求：从零搭机械、手写驱动、PID 调参、云端后端、量产工艺。

---

## 3. 课前准备（教师，约 3 小时）

### 3.1 硬件：全部预装、预接线

- [ ] 6 个工位机械臂装好，三个舵机 ID = 1/2/3，方向确认。
- [ ] 灯头：COB + 铝板 + 白色反光膜 + 扩散片装好。
- [ ] 电气：12V 母线、8P Hub、buck 5V、TTL Adapter、BH1750、KY-040、MOS 全部接好。
- [ ] 每个工位跑通基线固件：`scan`/`pos`/`led`/`lux` 都能用。
- [ ] 留 1 个「黄金工位」，课上做对照。
- [ ] 备用：ESP32 ×2、TTL Adapter ×1、舵机 ×1、5264 线 ×4、保险丝 ×4。

> 这节课**不接线**。接线是上一版课程（[4h-course.md](4h-course.md)）的内容；AI 课把时间全部留给「规格 → 生成 → 验证」。

### 3.2 软件：所有工位预装

- [ ] **Arduino IDE 2.x**：学生看代码、看串口、手动烧录用。
- [ ] **arduino-cli**：agent 编译/烧录/读串口用；与 IDE 共用同一套 core 和 libraries。
- [ ] ESP32 core 3.x + 库（SCServo、BH1750、ESP32Encoder）。
- [ ] 串口驱动（CH340/CP210x）装好，端口号固定。
- [ ] Python 3 + `pyserial`（测试脚本用）。
- [ ] AI agent 可用（Claude Code / Codex / Cursor 任选），并授予：
  - 读工程文件
  - 运行 `arduino-cli compile`
  - 运行 `arduino-cli upload -p COMx`
  - 运行 `python tools/monitor.py COMx 115200 5`
- [ ] 每个工位一个 `station.env`，写明端口号，避免烧错板。

### 3.3 网络、账号与权限

- [ ] 每个工位能登录 AI agent（账号/API key），并跑通一次「读文件 → 改文件」。
- [ ] 网络稳定；准备离线兜底：教师预生成 2–3 个功能的 diff/固件，断网时直接演示。
- [ ] **预批准命令**：`arduino-cli compile/upload`、`python tools/monitor.py`、`python tools/test_*.py`。否则 agent 每步都弹确认，4 小时不够。
  - Claude Code：项目 `.claude/settings.json` 的 `permissions.allow` 加上述命令。
  - Codex：在 `AGENTS.md` 写明命令，或配置 approval policy 允许这些命令。
  - Cursor：开启 Agent 模式并允许终端命令。
- [ ] 给每个工位设 token/费用上限；演示用教师账号，学生用共享账号。
- [ ] 禁用 agent 的「自动提交/自动推送」；这节课不需要 git 远端。

### 3.4 项目模板

每个工位一份，学生只在这个目录里改：

```
lt100-station/
├── AGENTS.md              # AI 必须遵守的规则
├── hardware.md            # 硬件契约：引脚、ID、限位、安全姿态
├── sketch.yaml            # CLI 的 FQBN/端口；IDE 选同一组
├── lt100_station.ino      # 基线固件（已跑通）
├── tools/
│   ├── flash.sh           # 编译 + 烧录
│   ├── monitor.py         # 读串口 N 秒并打印
│   └── test_*.py          # 验收脚本
└── README.md              # 本工位怎么跑
```

基线固件已经实现：舵机扫描、`pos`、`led`、`lux`、串口 CLI。学生从「加功能」开始，不从零写。

### 3.5 Arduino IDE + arduino-cli 怎么共存

**结论：学生用 IDE，agent 用 CLI，同一套 core、同一个 sketch 文件夹。**

`sketch.yaml` 示例：

```yaml
default_fqbn: esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,CDCOnBoot=cdc
default_port: COM5
```

三条规则：

1. **端口只有一个**：IDE 的串口监视器打开时，agent 不能烧录；约定「烧录前关监视器」，或者 agent 统一用 `tools/monitor.py`。
2. **FQBN 只有一个**：CLI 从 `sketch.yaml` 读；IDE 里手动选同一组（16MB / OPI PSRAM / CDC），或用 sketch profile。避免「学生烧的和 agent 编的不是同一个」。
3. **改代码只有一个写者**：agent 改 `.ino` 时，学生不要在 IDE 里同时编辑；IDE 只用来「看 + 烧 + 看串口」。

> 「一键安装」只对 IDE 本体成立；ESP32 core + 库还要装。课堂做法：一台母机装好，复制 `Arduino15` 目录或离线包到 6 台，别让 6 个工位同时下 1GB。

### 3.6 为什么这节课不用 PlatformIO

PlatformIO 更好，但更适合「工程」，不适合「4 小时第一次课」：

| | Arduino IDE + CLI | PlatformIO |
|---|---|---|
| 安装 | IDE 一键 + core | VS Code + 插件 + 平台包 |
| 学生熟悉度 | 高 | 低 |
| Agent 友好 | CLI 够用 | 更好 |
| 库版本锁定 | 手动 | `platformio.ini` |
| 多板/CI | 一般 | 强 |
| 4 小时课 | **合适** | 过重 |

补充一句：**PlatformIO 不是必须 VS Code**，`pio` CLI 可以独立跑；但对学生来说，VS Code + 插件 + 平台下载还是比 Arduino IDE 多三步。

**迁移时机**：课程稳定、要接 CI、要同时维护多块板、要锁库版本时，再换 PlatformIO。第一次课不要换。

### 3.7 最佳实践（这节课）

1. **一台母机装好，克隆到 6 台**：IDE + core + 库 + 驱动 + Python，全部离线可复现。
2. **一个工位一个 sketch 文件夹**：`hardware.md`、`AGENTS.md`、`sketch.yaml` 跟着走。
3. **两个界面，一个源**：学生用 IDE 看/烧/串口；agent 用 CLI 编/烧/读；源文件只有一份。
4. **命令封装**：`tools/flash.ps1`、`tools/monitor.py`，学生不记 FQBN/端口/波特率。
5. **预编译 + 备用板**：每轮开始前教师先编译一次；烧坏直接换，不修。
6. **测试先行**：每个功能先有 `test_*.py`，再让 agent 写实现；没有测试的功能不算完成。

## 4. 硬件契约（hardware.md 的核心）

AI 最容易犯的错是「随手改引脚」「删掉限位」「用阻塞延时」。契约就是给它划红线。

| 项目 | 值 | 约束 |
|---|---|---|
| 舵机总线 | UART2，TX=17，RX=18，1Mbps | 不许改波特率/引脚 |
| 舵机 ID | 1=肩，2=肘，3=腕 | 不许重编号 |
| 软限位 | 肩 -20~80°，肘 0~110°，腕 -30~60° | 不许删/放宽 |
| BH1750 | I2C，SDA=8，SCL=9，0x23 | 不许换地址 |
| LED PWM | GPIO4，LEDC 5kHz，12bit | 不许改频率低于 3kHz |
| 编码器 | CLK=5，DT=6，SW=7 | 不许占用中断做 I2C |
| 12V 检测 | GPIO1，分压 1/5 | 可选 |
| 安全 | 上电不动、软限位、力矩限制、离线降级 | **任何一条都不许删** |

**给 AI 的一句话**：引脚、ID、限位是硬约束；你可以加功能，但不能改这些。

## 5. Agent 规则（AGENTS.md / CLAUDE.md）

```markdown
# 工作规则

1. 改代码前先读 hardware.md 和本文件。
2. 不许改引脚、舵机 ID、软限位、安全限制。
3. 每次改动必须走完：编译 → 烧录 → 读串口 → 记录证据。
4. 不许用 delay() > 10ms；用 millis() 或状态机。
5. 不许在中断里做 I2C/串口。
6. 传感器/舵机失败必须有降级路径，不许死等。
7. 烧录前确认 station.env 里的端口号。
8. 不许把「编译通过」当成功能完成；必须有硬件行为或串口证据。
9. 不确定时先问，不要猜引脚。
10. 烧录前确认 IDE 的串口监视器已关闭，端口没有被占用。
11. 不要在 IDE 里同时编辑文件；agent 改代码时，IDE 只用于查看/烧录/看串口。
```

> Claude Code 用 `CLAUDE.md`，Codex 用 `AGENTS.md`，内容一样。规则要短、可执行，不要写长篇。

## 7. 功能菜单（每组选 1–2 个）

| # | 功能 | 输入 | 输出/验收 |
|---|---|---|---|
| 1 | 自动调光 | BH1750 lux | 遮住传感器 2s 内 LED 变亮；移开变暗；1 分钟内不振荡 |
| 2 | 编码器 UI | KY-040 旋转/按键 | 旋转 10 格亮度变化约 10%；按下切预设；串口打印 |
| 3 | 姿态预设 | `go 1/2/3` | 3s 内到位，角度误差 ≤2°；软限位不越界 |
| 4 | 平滑运动 | `go n` | 无突然甩动；加速度可调；不触发堵转 |
| 5 | 人走灯灭 | 人体感应 | 无人 30s 渐暗；有人渐亮；误触发可调 |
| 6 | 故障降级 | 拔舵机/传感器 | 打印 `ERR ...`，其余功能继续；不重启 |
| 7 | 串口 CLI 增强 | 命令 | `help` 列出全部；错误命令有提示；不崩溃 |
| 8 | WiFi 遥测（可选） | 手机/PC | 能读角度/温度/lux；断网不影响本地 |

**规格模板**（学生填一页）：

```
功能：
输入：
输出：
验收命令/现象：
不能碰的红线：
失败时应该怎样：
```

## 8. 测试脚本（AI 的裁判）

每个功能配一个可运行的测试，AI 改完必须跑：

| 脚本 | 做什么 | 通过标准 |
|---|---|---|
| `test_scan.py` | 发 `scan` | 返回 1/2/3 |
| `test_limits.py` | `move 1 999` | 角度被钳到 max，舵机不堵转 |
| `test_presets.py` | `go 1/2/3` + `pos` | 角度误差 ≤2° |
| `test_auto_dim.py` | 遮/不遮传感器，读 `lux` 和 `led` | 2s 内变化，1 分钟不振荡 |
| `test_offline.py` | 拔舵机 2，发 `pos` | 打印 `ERR servo 2 offline`，1/3 仍可用 |
| `test_encoder.py` | 模拟/手动旋转 | 亮度步进正确，按键切预设 |

> AI 最怕「没有反馈」。测试脚本就是把「硬件现象」变成「可读的 PASS/FAIL」。

## 9. 验收与评分

| 项目 | 权重 | 标准 |
|---|---|---|
| 功能演示 | 40% | 选定的功能在硬件上可重复演示 |
| 证据 | 20% | 串口日志、测量值、照片/视频，能复现 |
| 规格质量 | 20% | 输入/输出/验收/红线/失败路径都写清楚 |
| 代码审查 | 10% | 无阻塞延时、无越界、有降级、没删安全限制 |
| 交叉验收 | 10% | 能按别人的测试脚本验收并给出证据 |

**一票否决**：删软限位、改引脚导致短路、无降级导致整机死机、烧错板。

## 10. AI 常见错误（教师重点讲）

| 错误 | 现象 | 怎么发现 |
|---|---|---|
| 引脚冲突 | 舵机不动/传感器读不到 | 对照 hardware.md，量引脚 |
| 阻塞延时 | 按键/串口卡顿，自动调光振荡 | 代码审查 + 响应测试 |
| 越界 | 舵机撞灯罩/堵转发热 | `move 999` 测试 |
| 传感器失败未处理 | 拔掉 BH1750 后整机卡死 | 拔线测试 |
| 串口占用 | 烧录失败/监视器打不开 | 关闭监视器再烧 |
| 幻觉 API | 编译报错/库不存在 | 编译日志 |
| 改安全限制 | 力矩限制被删，夹手 | 代码审查 |

**教学价值**：AI 写代码很快，但**它不知道物理世界的边界**。学生的价值是提供边界、验收和取舍。

## 11. 教师兜底

- **黄金工位**：一台完整可演示的机器，任何组卡住就对照。
- **预编译 bin**：每轮开始前，教师先编译一次，确认工具链没坏。
- **备用板**：烧错/烧坏直接换，不修。
- **降级演示**：如果某组 AI 一直失败，切回基线固件，手动演示功能，记录失败原因。
- **时间不够**：砍掉第二轮和交叉验收，保底「第一轮功能 + 拔线降级」。

**最低可交付**：每组有一个功能在硬件上可演示，并有一页规格 + 一段串口证据。
